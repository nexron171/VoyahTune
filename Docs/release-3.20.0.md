# VoyahTune 3.20.0

## Изменения

- Кнопка «Обновления VoyahTune» в разделе «Другое» открывает новую Activity Updater
  с начальным экраном вместо завершённого результата. Найденный/скачанный релиз,
  активная операция и ошибка восстановления сохраняются.
- Новый интерфейс Updater 0.3.0 доставляется после основной OTA отдельным
  root-процессом. Предварительная установка через USB для этого не требуется,
  если установленная служба уже поддерживает нынешний формат payload/recipe.
- Поддержана прежняя служба без команды `finish`: кнопка «Завершить» и вход из
  RestoreMode сбрасывают представление результата; журнал службы сохраняется.
- Замена интерфейса проверяет подпись APK и хеши из подписанных метаданных релиза,
  сохраняет прежний системный APK и журнал. После замены выполняется дополнительная
  перезагрузка в P при подтверждённой нулевой скорости.
- После загрузки проверяются активный системный APK и versionCode PackageManager.
  При неподтверждённой регистрации предусмотрено восстановление прежнего APK.

## Совместимость и ограничения

Root-служба Updater, её init-контракт и bootstrap при OTA сохраняются.
Формат payload остаётся schema 4, recipe — `qinggan-v3` schema 3, минимум Installer —
1.2.0. Новые файловые артефакты поддерживаются существующим исполнителем.
[Механизм и порядок проверок](updater-ui-ota.md).

Существующий GUI устанавливает payload и удаляет его по сохранённому recipe.
Для актуализации встроенного аварийного remover нужна пересборка GUI macOS Universal,
Windows x64/x86: его recipe теперь содержит два новых файла. Версия Installer
не повышается; это совместимое изменение ресурсов и не условие OTA-доставки.
Совместимая пересборка Installer 1.4.0 для этого релиза публикуется отдельно в
`Installers/1.4.0/builds/3.20.0/`, сохраняя прежний комплект `Installers/1.4.0/`.

Локальные тесты и release-сборка не подтверждают замену системного APK на автомобиле.
Приёмка на официальных SE и Sport+ 2025–2026 с Android 11 выполняется отдельно:
системная регистрация APK, сохранение UID/данных, дополнительные перезагрузки,
восстановление после прерывания и поведение при движении ещё требуют проверки на ГУ.

## Сборка и публикация

Payload собран из чистого коммита `3d5224c699b3c91440fb8276eda31f2686fc89ae`:
Native/RestoreMode 3.20.0 (versionCode 3020000), Updater 0.3.0 (versionCode 3).
Подписи APK совпадают с 3.19.0; подписанные runtime hashes подтверждают оба новых
артефакта. Финальный payload содержит 29 файлов и принят проверяющим кодом
Installer из коммита `36f1d55`, предшествующего механизму доставки UI.

Выполнены 31 Rust-тест Updater, 40 Rust-тестов Installer workspace,
JVM-тесты и assembleDebug Updater, release-сборка Android APK/ARM64,
проверки синтаксиса loader и фонового запуска обслуживания UI,
тесты раздельного префикса публикации установщиков.
Для Installer проверены macOS arm64+x86_64, архивы NSIS, архитектуры Windows
x64/x86 и ADB x86, а также `verify-host` для всех трёх комплектов ресурсов.
