# Как собрать системные логи для диагностики VoyahTune

Эта инструкция поможет сохранить системный журнал Android (logcat) в текстовый файл на компьютере с Windows или macOS. Лучше начать запись до появления проблемы, воспроизвести её и затем остановить запись.

## Подготовка автомобиля

1. Включите головное устройство (ГУ) и отладку по USB. Подключение, подходящий кабель и вход в инженерное меню описаны в [основной инструкции](../readme.md#инженерное-меню-и-отладка-по-usb).
2. Подключите компьютер к USB-порту автомобиля, предназначенному для ADB. Используйте кабель и переходники согласно основной инструкции проекта.
3. Если на экране ГУ появится запрос разрешения на отладку, подтвердите его.
4. Отключите от компьютера другие Android-устройства и закройте Android-эмуляторы, чтобы ADB видел только автомобиль.

Если проблема уже произошла, не перезагружайте ГУ и не очищайте журнал. Сначала сохраните имеющиеся сообщения по разделу «Если проблема уже произошла» ниже: старые записи постепенно вытесняются из памяти.

## Windows

### 1. Подготовьте ADB

1. Скачайте **SDK Platform-Tools for Windows** с [официальной страницы Android](https://developer.android.com/tools/releases/platform-tools).
2. Полностью распакуйте ZIP-архив, например в `C:\VoyahLogs`. Внутри появится папка `platform-tools`.
3. Откройте папку `platform-tools`, в которой находится `adb.exe`.
4. В адресной строке Проводника введите `cmd` и нажмите **Enter**. Откроется командная строка в этой папке.

Команды ниже предназначены для **cmd**. Если используете PowerShell, заменяйте `adb.exe` на `.\adb.exe`.

### 2. Проверьте подключение

```bat
adb.exe devices
```

В списке должна появиться одна строка с устройством и статусом `device`, например:

```text
List of devices attached
0123456789ABCDEF    device
```

Идентификатор вашего устройства будет другим. При статусах `unauthorized`, `offline` или пустом списке используйте раздел «Если ADB не видит автомобиль» ниже.

### 3. Запишите проблему в файл

Перед воспроизведением проблемы выполните:

```bat
adb.exe logcat -b all -v threadtime "*:V" > logcat.txt
```

1. Оставьте командную строку открытой. Отсутствие новых сообщений в окне — нормально: они записываются в файл.
2. На ГУ повторите действия, после которых возникает проблема.
3. Запишите примерное время её появления.
4. Подождите ещё 10–20 секунд и нажмите **Ctrl+C** в командной строке.
5. Найдите файл `logcat.txt` в той же папке `platform-tools`, где находится `adb.exe`.

Чтобы открыть файл из командной строки:

```bat
notepad logcat.txt
```

## macOS

### 1. Подготовьте ADB

1. Скачайте **SDK Platform-Tools for Mac** с [официальной страницы Android](https://developer.android.com/tools/releases/platform-tools).
2. Распакуйте ZIP-архив двойным щелчком. Появится папка `platform-tools`.
3. Откройте приложение **Терминал** через Spotlight или папку «Программы → Утилиты».
4. Введите `cd` и пробел, перетащите папку `platform-tools` из Finder в окно Терминала, затем нажмите **Enter**.

Если папка находится в «Загрузках», можно выполнить:

```sh
cd "$HOME/Downloads/platform-tools"
```

### 2. Проверьте подключение

```sh
./adb devices
```

Должно отобразиться одно устройство со статусом `device`. Если на ГУ появился запрос на отладку, подтвердите его и повторите команду.

### 3. Запишите проблему в файл

Перед воспроизведением проблемы выполните:

```sh
./adb logcat -b all -v threadtime "*:V" > logcat.txt
```

1. Оставьте Терминал открытым. Отсутствие новых сообщений в окне — нормально: они записываются в файл.
2. На ГУ повторите действия, после которых возникает проблема.
3. Запишите примерное время её появления.
4. Подождите ещё 10–20 секунд и нажмите **Control+C** в Терминале. Используйте именно **Control**, а не Command.
5. Найдите файл `logcat.txt` в папке `platform-tools`.

Чтобы показать файл в Finder:

```sh
open -R logcat.txt
```

## Если проблема уже произошла

Сразу после подключения сохраните сообщения, которые ещё остались в памяти ГУ.

**Windows, cmd:**

```bat
adb.exe logcat -b all -v threadtime -d "*:V" > logcat-snapshot.txt
```

**macOS, Терминал из папки `platform-tools`:**

```sh
./adb logcat -b all -v threadtime -d "*:V" > logcat-snapshot.txt
```

Команда с `-d` завершится сама; нажимать Ctrl+C не нужно. Файл `logcat-snapshot.txt` появится в текущей папке. Он содержит только сохранившиеся сообщения: давняя ошибка могла уже исчезнуть из журнала. В таком случае начните обычную запись и воспроизведите проблему ещё раз.

## Что отправить разработчику

- Файл `logcat.txt` или `logcat-snapshot.txt`. Если файл большой, упакуйте его в ZIP.
- Версию VoyahTune, модель автомобиля и версию прошивки ГУ, если они известны.
- Краткое описание: какие действия выполнялись, что ожидалось и что произошло.
- Примерное время ошибки; укажите, смотрели ли вы время на ГУ или на компьютере.

Перед отправкой откройте файл и убедитесь, что в нём есть строки журнала. Если файл пустой или в терминале появилась ошибка, проверьте подключение и повторите запись.

При повторном сборе меняйте имя файла, например на `logcat-2.txt`: команда с `>` перезаписывает существующий файл с таким же именем.

## Если ADB не видит автомобиль

| Что отображается | Что сделать |
| --- | --- |
| `unauthorized` | Подтвердите разрешение на отладку на экране ГУ, затем повторите проверку устройств. |
| `offline` | Переподключите кабель и повторите проверку устройств. |
| Список устройств пустой | Проверьте отладку по USB, кабель и выбранный USB-порт. На Windows может понадобиться ADB-драйвер для ГУ. |
| `more than one device/emulator` | Отключите остальные Android-устройства и закройте эмуляторы, затем повторите команду. |
| Windows не находит `adb.exe` | Откройте `cmd` именно в распакованной папке с `adb.exe`. В PowerShell используйте `.\adb.exe`. |
| macOS сообщает `no such file or directory` при запуске `./adb` | Перейдите в распакованную папку `platform-tools` через `cd`. |

## Какие сообщения собираются

`-b all` запрашивает все доступные буферы logcat, включая сообщения приложений, системы и аварий. `-v threadtime` сохраняет время, уровень сообщения, тег и идентификаторы процесса и потока. `"*:V"` включает все уровни сообщений, которые уже попали в журнал. Символ `>` направляет вывод в файл на компьютере.

Не ограничивайте журнал только процессом VoyahTune: причина проблемы может быть в связанных системных службах. Не выполняйте `logcat -c` перед сохранением уже случившейся ошибки — эта команда очищает журнал.

Описание параметров: [документация Android Logcat](https://developer.android.com/tools/logcat).
