# Загрузчик Java-агентов

Единый runtime состоит из Go-supervisor, ARM32/ARM64 helper, native bootstrap и общих Java-модулей.
Актуальные исходники, команды и состав находятся в [Packaging/new](../Packaging/new/README.md).
Прежний shell/JS backend удалён; история его реализации сохранена в Git.

Процессы обнаруживаются независимо. ACC имеет ограниченный приоритет 45 секунд:
остальные цели освобождаются после его полного ACK, ошибки либо истечения срока.
Для каждой цели supervisor объединяет статические и динамические модули в один
план и использует один resident, привязанный к boot ID/PID/startTicks/UID.

Helper подтверждает attach, восстановление состояния tracee и detach. `active`
возможен только после его завершения и полного Java ACK для текущей revision и
всех обязательных модулей. Частичный ACK, прежняя identity, текстовая ready-запись
и незавершённый helper не подтверждают готовность.

Клавиатура EN/RU фиксируется до смены процесса QGIME. Apollo проверяет разрешение
Native для текущего boot. Повторы и быстрые перезапуски целей ограничены; ошибка
одного динамического клиента не блокирует остальные процессы.

В разделе «Другое» диагностика показывает root-службу OTA, Native, обмен настройками,
загрузчик, комплект инжекторов, resident/JNI, Java runtime и все статические и наблюдаемые
динамические агенты. Зелёный индикатор означает подтверждённую работу, жёлтый — ожидание,
отключение или частичную готовность, красный — ошибку или потерю актуального подтверждения.
Нажатие на строку открывает полное описание, включая причину, PID и ABI.

Loader публикует root-only `publishRuntimeStatusV2` каждые 5 секунд. Запись содержит
boot/process identity, поколения native/Java, время подтверждения и причины ошибок.
UI проверяет возраст записи (20 секунд) и текущий Android boot; прежняя загрузка или
устаревший ACK не остаются зелёными. Опрос IPC работает только при видимом блоке,
а задержка обновления UI более 25 секунд снимает подтверждение всех его индикаторов.
`publishHookStatusV1` сохранён для совместимости с прежним интерфейсом.

После сбоя supervisor восстанавливает resident по приватному durable journal без
повторного attach. При блокировке установки recovery и control остаются доступны,
но новые инъекции закрыты. Quiesce проверяет peer/identity и ждёт helper/worker drain.
Если живой supervisor недоступен, тот же установленный loader выполняет offline drain.
Неопределённое состояние требует ремонта; оно не превращается в успешный ACK.

USB/OTA сначала блокируют admission и подтверждают quiesce, затем останавливают
сервис, заменяют код, очищают точные старые пути и перезагружают Android. Маркер
текущего boot запрещает подключение нового поколения к старым живым процессам.
