# Архитектура VoyahTune Installer

Актуальное обязательное правило: GUI/CLI исполняет Rust-порт классических
install/remove без дополнительных проверок автомобиля и причин остановки.
[Полная карта шагов, исходники и правила сопровождения](installer-classic-port.md).

## Компоненты

- `Installer/desktop`: Tauri + Svelte, выбор Full/Light/удаления и DNS, ручное
  подтверждение автомобиля, прогресс, журнал, сохранение отчёта.
- `Installer/crates/installer-cli`: единый интерфейс для GUI и скриптов;
  `info`, `verify`, `devices`, `plan`, `apply`, `apply-plan`.
- `Installer/crates/installer-core`: порт действий, ADB, информационная
  инвентаризация, события JSONL и хранение результатов на компьютере.
- `Installer/crates/installer-build`: сборка Full/Light APK и всего payload.
- `Installer/scripts`: сборка/упаковка релиза и нативных инструментов.
- `Packaging/installer`: классические сценарии, эталон логики порта.

`engine.rs::execute()` управляет шагами. Проверяемые команды и best-effort команды
различаются по соответствующим веткам старых скриптов; ошибки вторых только попадают
в журнал. `plans.rs::classic_steps()` задаёт отображение того же порядка.
`classic_commands.rs` содержит исходные тела adb shell, а не host-сценарий установки.
В Windows Rust вызывает комплектный adb.exe, POSIX-интерпретатор не требуется.

## Подключение и отображение состояния

Первый экран предлагает Full, Light или единое удаление. Удаление не зависит от
того, какой набор был установлен, и использует полный remover.

Найденный автомобиль пользователь подтверждает вручную. Если устройство отсутствует,
несколько устройств, unauthorized или offline, показываются причина и «Обновить».
Есть подсказки про USB debugging в инженерном меню и рассчитанный код с выбором даты.
Если код не подходит — увеличить его на единицу или выбрать следующий день.

После подтверждения выполняется диагностическое чтение состояния. Metadata,
API/ABI, сведения о версии и файлах используются для пояснения в UI. Их отсутствие
или изменение inventoryToken не добавляет запрета установки. План — выбор действия
и показ шагов; решение продолжать конкретный шаг принимает порт старого сценария.

## Установка, удаление и подписи

Порядок Full/Light/remove и их различия зафиксированы в документе порта.
Согласованное отличие: при известном несовпадении подписи Native/RestoreMode
приложение удаляется с данными и устанавливается заново без дополнительного вопроса.
Matching key сохраняет данные. Ошибки Android, не связанные с подписью, не запускают сброс.
При remove подписи установленных APK не читаются.

Root, remount, backup, миграция init.logcat, boot-hook rollback, Native CE/DE lifecycle
и DNS выполняются по старым условиям. Никаких дополнительных ownership/hash/receipt
или persistent-lock preflight нет. Старый lock/owner очищается best effort.
Параллельная установка с разных приложений/компьютеров не координируется.

Отмена пользователя проверяется между шагами. Команды и ожидания имеют те же
условия завершения, что классический сценарий; новый общий timeout установки
не вводится. Подготовка GUI и диагностические запросы остаются отдельными от процесса.

## Прогресс и отчёты

Движок отправляет step-started/completed/failed, команды, stdout/stderr и итог.
GUI не вычисляет успех по проценту: он отображает результат движка. Шаги не теряются
при сокращении списка последних событий. Tauri capability разрешает подписку;
после окончания доступны сохранённые события и отчёт.

Журналы находятся в пользовательском каталоге приложения `operations/DEVICE/OPERATION/`.
`backup/` хранится рядом с операциями одного автомобиля и соответствует прежнему
host-каталогу backup. На автомобиле новая база состояния/блокировок не создаётся.
Внутренняя metadata payload нужна для поиска локальных файлов; ручной JSON для
разработчика не требуется. SHA/подписи комплекта проверяет сборка и явный `verify`;
GUI читает комплект командой `info`, установка проверяет файлы по старым правилам.

## Доставка и релизы

Установщик автономен: полный Full/Light payload и ADB внутри. macOS Universal
(arm64+x86_64), Windows x64, Linux x64. Драйвер USB при необходимости устанавливается
отдельно, ADB пользователю устанавливать не нужно. Linux GUI требует графическую
сессию и glibc уровня Ubuntu 22.04; CLI доступен отдельно.

Готовые бинарники только в игнорируемом Releases. По умолчанию `make_release.sh`
собирает старые ZIP со скриптами. `--installers` собирает все платформы; `--mac`,
`--windows`, `--linux` выбирают их. Повторный локальный выпуск заменяет прежний
после успеха. [Подготовка среды](../Installer/BUILDING.md), [выпуск](releasing.md).
