# Архитектура VoyahTune Installer

Svelte → Tauri commands → `installer-core` → встроенный ADB. Отдельного CLI-процесса
нет. Блокирующая работа выполняется в workers, события библиотеки передаются в Tauri
и в журнал. Cancel и согласие на VoyahHlCTRL — типизированные запросы. Mutex состояния
не удерживается во время ADB/ожидания согласия; busy-state исключает второй запуск
и закрытие окна до безопасной остановки. Аварийное завершение ОС не заменяет rollback:
прерванная установка требует повторной проверки и восстановления.

`session::plan` — общий API диагностики/планирования для GUI и тестов.
`engine::execute` — порядок специальных процедур и файлового recipe.
`plans::classic_steps` описывает те же фазы для UI. `classic_commands.rs` содержит
device-side shell из классических скриптов; GUI не запускает host `.sh/.bat`.
На Windows применяется встроенный adb.exe, локальный POSIX shell не требуется.

Каталог, requirements, ZIP, SHA-256, распаковка и кэш находятся в `catalog.rs`.
Совместимость проверяется до автомобильных команд. Payload schema 4 включает
декларативный recipe и по одному Native/RestoreMode APK.
[Контракт](installer-protocol.md).

Сетевая загрузка в `catalog/download.rs` сохраняет частичный ZIP в
`downloads/partial/<sha256>.part` под общей блокировкой кэша. Повторный выбор релиза,
включая перезапуск GUI, продолжает загрузку по фактическому размеру этого файла.
Запросы HTTP Range получают части до 4 МиБ; каждый запрос ограничен 120 секундами,
подключение — 10 секундами, получение заголовков — 30 секундами. Ограничения
на суммарную длительность скачивания всего релиза нет. Прежний таймаут тела ответа
30 секунд ограничивал весь ZIP, а не паузу между порциями данных.

Обрывы, таймауты и временные HTTP 408/429/500/502/503/504 вызывают до пяти повторов
без продвижения с паузами 1, 2, 4, 8 и 16 секунд. Полученные новые байты сбрасывают
этот счётчик. Во время повторов GUI сохраняет процент и объём загрузки. Отмена
проверяется между чтениями и во время пауз; уже начавшийся блокирующий сетевой
вызов может завершаться до своего таймаута. Ошибки диска и некорректные ответы
не повторяются автоматически.

Ответ 206 принимается только с соответствующими диапазоном, общим размером
и длиной. Если сервер игнорирует Range и возвращает 200, сохранённый префикс
заменяется полным ответом с начала. После получения всех байтов проверяется SHA-256:
неверный файл удаляется, чтобы следующий выбор начал чистую загрузку. Частичный ZIP
не показывается как скачанный релиз и не используется для установки. После успешной
проверки и распаковки файл `.part` удаляется; при отмене или сетевой ошибке сохраняется.
Изменение требует пересборки GUI, но сохраняет версию установщика и требования payload.

Начиная с Installer 1.2.0, первая USB-установка включает root-службу обновлений
и независимый интерфейс. Desktop и OTA используют общую блокировку на ГУ; перед
ремонтом desktop сохраняет прежние OTA-логи в отчёт. Подробности —
[устройство updater](ota-updater.md) и [приёмка](ota-acceptance.md).

## Подключение и установка

Первый экран выбирает версию VoyahTune, затем установку или удаление. Удаление известно
установщику без полного payload. На компьютере сохраняются recipe и remove-ресурсы
установленных/прерванных релизов отдельно от download cache. Для неизвестных
будущих компонентов нужен соответствующий совместимый payload либо новый GUI.

Пользователь подтверждает единственный подключённый автомобиль. Отсутствие устройства,
несколько устройств, unauthorized/offline показываются до планирования. Код инженерного
меню рассчитывается для даты UTC+8 с возможностью ручного выбора даты.

Plan фиксирует версию GUI, payload/recipe digest, операцию, фазы и recipe.
Backend сохраняет план и выбранный путь; смена manifest после проверки отклоняет apply.
Файлы повторно проверяются. Выбор DNS на экране проверки остаётся явным параметром.
API/ABI и inventoryToken служат диагностике и не вводят новые условия совместимости ГУ.

Root/remount, backup, CE/DE, смена подписи, boot transaction/rollback и DNS сохраняют
[прежние специальные процедуры](installer-classic-port.md). Разделения на варианты установки и специальной миграции между ними нет.
При том же ключе APK обновляются с сохранением данных; смена ключа сбрасывает только
соответствующее приложение. Remove не проверяет подписи установленных приложений.
VoyahHlCTRL — отдельное согласие на удаление с backup, reboot и повторной проверкой.

Остановка runtime допускает уже отсутствующие компоненты: пустое состояние init-службы
означает, что она остановлена; `pkill` с кодом 1 не создаёт предупреждение; пустой список
принадлежащих релизу Frida-процессов не передаётся в `kill`. Ошибки остановки существующей
службы и остальные ошибки команд сохраняются в диагностике.

## Результаты и упаковка

Events, plan, report и backup сохраняются в каталоге данных приложения на компьютере.
Download cache и recovery — соседние самостоятельные каталоги. Отчёт экспортируется из
GUI, включая идентичность payload при ошибке. Нет нового постоянного mutex на автомобиле.
Старые lock/receipt не используются как право владения устройством.

GUI содержит ADB и небольшой builtin-remover. По умолчанию полного payload нет.
macOS — Universal `.app`, Windows — x64 NSIS, Linux — x64 `.run` (графическая сессия
X11/XWayland, glibc уровня Ubuntu 22.04). Версия всех GUI-пакетов берётся из Cargo,
версия ZIP payload — из автомобильного релиза. Сборщик и тестовый драйвер не распространяются.

## Проверки

[Наблюдения предыдущей проверки на ГУ](installer-validation-2026-09-27.md) относятся
к прежнему контракту. Новый релиз требует отдельной проверки на автомобиле.
