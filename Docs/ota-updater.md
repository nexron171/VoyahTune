# Root-служба обновлений VoyahTune

Единая root-служба применяет тот же payload, что компьютерный установщик:
общие APK, RunYN по условию модели и runtime из `Packaging/new/`. Manifest и служба
используют `infrastructure: unified`; для первого внедрения нужен USB и Installer 1.8.3.
Последующие совместимые OTA не заменяют собственный executable службы.
[Контракт общего payload](installer-payload.md) · [Приёмка на ГУ](ota-acceptance.md).

Общие модели и проверки находятся в [release-core](../Installer/crates/release-core/src/lib.rs).
Сетевые операции выполняет Rust-служба с HTTPS и встроенными корневыми сертификатами.
Единственная проверка допуска — `minimumOtaVersion`. Размер/SHA-256 архива, подписи APK,
совпадение metadata, версий и capabilities не проверяются перед установкой.

## Рабочий цикл

Состояние сохраняется атомарно в `state.json`. Закрытие UI не отменяет действие.
Смена URL сбрасывает выбор; `sourceGeneration` проверяется после перезапуска.
ZIP распаковывается в новый закрытый каталог; ссылки, коллизии и выход из каталога
запрещены. После ошибки загрузка начинается заново, без HTTP Range.

В [сетевой реализации](../Updater/daemon/src/network.rs) общий лимит запроса
каталога — 60 секунд, архива — 3600 секунд, соединения — 20 секунд.
Для каталога дополнительно ограничено суммарное получение тела ответа: 45 секунд.
У архива отдельного короткого лимита нет; действует общий часовой срок.
Эти параметры определяются установленным бинарником службы и меняются через USB.

Суточное расписание сохраняет время попытки до запроса, в том числе при ошибке сети.
В пределах загрузки используется также uptime; перевод часов назад откладывает запрос.
Между холодными загрузками интервал зависит от системных часов. Фоновая проверка
не скачивает архив и не запускает установку.

В `preparing` служба повторно читает инструкции установки из payload, определяет модель для
условных пакетов, подготавливает remount и DNS. В текущем общем исполнителе нет
блокирующей CAN-проверки P/скорости или сверки fingerprint перед записью; не следует
описывать их как выполненные. Обновление проводят на стоящем автомобиле в P
при стабильном питании. Wake lock не гарантирует сохранение питания автомобиля.

Ошибка до записи возвращает `verified`: релиз остаётся доступным для повторной
попытки. Перед блокировкой приложений сохраняется `applying`. С этой границы ошибка
или прерывание требует USB-восстановления: автоматического продолжения и отката нет.

Исполнитель создаёт `voyahtune-update.block`, останавливает загрузчик, Native и
рабочие процессы RestoreMode. Процесс `:ota` сохраняется. Файлы устанавливаются
через rename на целевой файловой системе, применяются права и очистка из recipe.
Native обновляется также через PackageManager, чтобы прежний APK из `/data/app`
не перекрыл системную копию. При отсутствующем Native DE выполняется
`force-stop --user 0` → `uninstall -k --user 0` → `install-existing --user 0 --wait`.
RunYN устанавливается по условию `except-h97xy`.

На H97X/H97Y перед заменой RestoreMode служба применяет общий структурный патчер
шрифтов навигации в QNX-темах через qconn/TCP. Неизвестные темы пропускаются;
это не новая проверка допуска OTA. Оригиналы и журнал сохраняются в QNX для
восстановления при удалении компьютерным установщиком.
[Поведение и откат](installer-payload.md#шрифты-навигации-h97xh97y).

RestoreMode устанавливается последним APK после Native, RunYN, DNS, шрифтов и sync.
PackageManager закрывает UI, а внешний root-исполнитель продолжает работу:
фиксация `reboot-pending`, снятие блока, sync и reboot. При ошибке записи блок
сохраняется для USB-восстановления. [Порядок доставки UI](updater-ui-ota.md).

При OTA бинарник службы, `voyahtune.updater.rc` и bootstrap остаются установленными;
их копии в архиве пропускаются. Общий recipe заменяет runtime и удаляет известные
старые загрузчики/хуки. Изменение init загрузчика допускается общим исполнителем.

После перезагрузки служба ждёт Android, проверяет/восстанавливает Native DE,
повторно читает инструкции установки из payload. Затем вызывает `voyahtune-loader --check-hooks`: проверяются
supervisor, агенты и идентичность целевых процессов. Для временных ошибок
предусмотрены ограниченные повторы. Ошибка hooks не позволяет зафиксировать успех.
Это не полная проверка автомобильных функций; они проверяются при приёмке.

При успехе сохраняется `committed` и очищается кэш. Ошибка применения или проверки
после загрузки переводит службу в `repair-required`; подробности остаются в журнале.
Кнопка «Завершить» возвращает экран к проверке обновлений, но не снимает блокировку
незавершённой записи и не заменяет USB-восстановление.

## Процессы и запуск

[Updater](../Updater/README.md) содержит Rust executable и общую Android-библиотеку UI.
Activity входит в RestoreMode и работает в процессе `:ota`.
[Init rc](../Packaging/system/voyahtune.updater.rc) запускает единственный
`voyahtune_updater` после `post-fs-data` от root, с `group inet` и `su` domain.
Init перезапускает завершившийся процесс; дополнительный файловый lock исключает
второй экземпляр. Служба не принадлежит процессу обновляемого приложения.
Android init предоставляет [сокет и управление перезапуском](https://android.googlesource.com/platform/system/core/+/refs/tags/android-11.0.0_r12/init/README.md).

USB-установщик 1.8.3 устанавливает единую root-службу, RestoreMode со встроенным UI и rc совместно:

| Компонент | Путь | Владелец / права |
| --- | --- | --- |
| Служба | `/data/local/bin/voyahtune-updater` | root:root / 0755 |
| Интерфейс | `ru.big.town.restoremode/.OtaActivity`, процесс `:ota` | APK в `/data/app`, UID RestoreMode |
| Init | `/system/etc/init/voyahtune.updater.rc` | root:root / 0644 |
| Состояние и логи | `/data/local/voyahtune-updater/` | root:root / 0700 |

Пути входят в recipe; установщик проверяет службу и IPC, поддерживает удаление
и сохраняет OTA-логи перед повторной установкой. Общий lock исключает параллельное применение.
Доступность `su` domain, сокета, сети и порядок загрузки на OEM ROM ещё требуют проверки.
Сама новая rc не переключает SELinux; существующая интеграция загрузчика задаёт его режим.
Init должен поддерживать службу постоянно, в том числе при открытии VoyahTune;
приложение не получает команду запуска произвольного root-процесса.

## Интерфейс и закрытый канал

Кнопка «Обновления VoyahTune» на странице «Другое» RestoreMode открывает
`ru.big.town.restoremode.OtaActivity` в отдельном процессе `:ota`.
При открытии из RestoreMode задача OTA очищается и создаётся новая Activity:
старые диалоги и положение прокрутки не восстанавливаются.
Интерфейс отправляет службе `finish`: завершённый
результат сбрасывается до начального экрана проверки. Служба не меняет активную
операцию, найденный или скачанный релиз и состояние `repair-required`. Обычный запуск из Android launcher
сохраняет текущий результат. Из внешнего Intent используется только этот флаг;
архивы, адреса и команды из него не принимаются.
При отсутствии `finish` в прежней службе интерфейс скрывает завершённый результат
локально; журнал службы сохраняется. Автоматический вход не скрывает активную
операцию или ошибку.

В интерфейсе 0.4.0 на любой ошибке и на успешном результате есть «Завершить»,
возвращающая на начальный экран. Явное нажатие отправляет `finish` с необязательным
boolean `reset_errors: true` (по умолчанию false). Новая служба сбрасывает неактивный
результат, выбор релиза, ошибку и прогресс. Установленная версия, её хеш, настройки
и расписание сохраняются. Старые службы, отклоняющие флаг, поддерживаются через
локальный сброс представления; повторный `status` не возвращает закрытую ошибку.
Новая операция или изменившееся состояние снова показываются.
При недоступной службе экран сбрасывается локально, а команда откладывается
до восстановления связи. Активная операция не отменяется. После ошибки записи
`repair-required` и блокирующий файл сохраняются: для повторной OTA нужно
USB-восстановление, даже если представление ошибки закрыто.
Интерфейс обновляется в составе RestoreMode по [контракту доставки](updater-ui-ota.md).

Собственный интерфейс отправляет службе JSON-строку через сокет init
`/dev/socket/voyahtune_updater`. Допустимы `status`, `get_settings`, `set_settings`,
`set_catalog_url`, `check`, `download`, `apply`, `finish`, `dismiss` и `logs`; неизвестные команды и поля отклоняются. Лимит запроса — 8192 байта,
таймаут обычного ответа — 5 секунд, для чтения/сохранения настроек — 45 секунд. Ответ содержит `schema: 1`, `ok` и данные либо подробную `error`.

Предусмотрена root-диагностика `voyahtune-updater --health`: команда
запрашивает `status` у работающей службы через тот же сокет, с ограничением времени
и размера ответа. UID 0 допускается только к `status`; команды изменения состояния
по этому пути запрещены. В ответе указано `infrastructure: "unified"`.

Для остальных клиентов перед чтением запроса служба сверяет `SO_PEERCRED` с реестром PackageManager.
Принимается только уникальный UID RestoreMode без shared UID, активный APK из
`/data/app` и подпись, совпадающая с проверенным системным Native. Путь берётся из
`packages.xml`; APK принадлежит root или system, не доступен для записи группе/остальным
и не содержит симлинков. Подписи проверяются повторно при смене идентичности файлов.
UI проверяет UID 0 сервера.
Подмена сокета или UID через Intent production-приложения отсутствует.
Доступ к сокету дополнительно зависит от OEM SELinux; его файловый режим допускает
соединение, но не заменяет проверку клиента внутри службы.

## Каталог и настройки

Встроенный адрес единого каталога:

```text
https://voyahtune.ru/api/v1/releases
```

Локальные JSON-индексы не ведутся. OTA выбирает версии без инфраструктурного
суффикса, включая beta, если они присутствуют в выбранном источнике.

Владелец может изменить URL в собственном экране обновления. Допустим другой HTTPS-хост,
но запрещены логин/пароль в адресе и fragment. Адрес сохраняется в `settings.json`
с правами 0600 через временный файл, fsync и rename; не сбрасывается после перезапуска.
При запуске единой root-службы прежние стандартные адреса GitHub/GitLab
автоматически заменяются новым API. Миграция сохраняется в `settings.json`,
увеличивает `sourceGeneration` и сбрасывает прежний список/выбор релиза
при обычном запуске. Незавершённое восстановление не прерывается.
Пользовательские и beta-адреса сохраняются.
Этап USB bootstrap очищает `state.json` и блокировку обновления, но не
`settings.json`. Кнопка возврата к адресу по умолчанию использует адрес установленной
root-службы; смена версии бинарника сама по себе не сбрасывает выбор каталога.
Повреждённые настройки сохраняются для диагностики, без молчаливого сброса.
`sourceGeneration` увеличивается при смене адреса; проверка/скачивание и повторный
запуск службы сверяют его, чтобы не применить выбор из прежнего каталога.
Смена URL не запускает скачивание. Контрольная сумма берётся из выбранного HTTPS-каталога.

## Логи и ошибки

Журнал `updater.log` закрыт для сторонних APK (0600); при 512 KiB сохраняется одна
предыдущая ротация. Просмотр и выгрузка журнала убраны из пользовательского UI.
Файлы сохраняются для диагностики через USB; служебная IPC-команда `logs` сохранена.
В журнал входят этапы загрузки, распаковки, установки, reboot и проверки запуска.

При ошибке экран показывает подробную причину и предлагает установку
через USB с компьютера. Если не работает сама служба, интерфейс сообщает об этом,
но прочитать её закрытые файлы без службы не может — необходим USB-доступ.
Текущее открытие экрана не зависит от запуска Native или RestoreMode.

### Системная запись логов

Экран «Логирование» в RestoreMode управляет [сборщиком root-службы](../Updater/daemon/src/application_log/mod.rs)
через авторизованный IPC `application_log` (capability `application-log-v1`).
Сбор всех буферов `logcat -b all` без фильтра PID, запись файла и HTTP выполняются
в фоновых потоках; закрытие или падение приложений не останавливает сбор.

Файл `/data/local/voyahtune-updater/application-log/system-log.txt` имеет права 0600
и ограничен 15 000 000 байт. Перед превышением лимита старый файл удаляется,
запись начинается заново. Остановка сохраняет файл, повторный старт дописывает его;
экран показывает последние 100 строк. Сохранённое включённое состояние возобновляет
запись при `post-fs-data`, включая доступные буферы текущей загрузки. События,
уже вытесненные из logd до запуска службы, восстановить невозможно.

Выгрузка останавливает запись и отправляет неизменяемый TXT через HTTPS multipart
на `https://voyahtune.ru/api/v1/application_sessions`. Повтор из диалога ошибки
сохраняет `sessionId`, версию и байты файла, учитывает задержку сервера. Отмена
и успешная выгрузка оставляют файл на ГУ; удаление выполняется отдельной кнопкой.
После подтверждения сервером диалог показывает крупный ID и QR-код чата Telegram.

Изменение root-службы доставляется через USB в payload. Новый Installer требуется
только при изменении его поведения, ресурсов или поддерживаемого контракта.


## Прогресс установки и DNS

Root-служба публикует `completedSteps` и `totalSteps` в состоянии. Счётчик увеличивается
только после успешного завершения группы операций: проверка условий и /system,
остановка приложений/loader, копирование файлов, права/очистка, Native, RestoreMode,
DNS и синхронизация. Процент относится к завершённым шагам, а не к оставшемуся времени.
Предварительная проверка остаётся в `preparing`, запись — в `applying`.
100% до reboot не означает `committed`; окончательный успех требует проверки запуска.
Старые journal без этих полей читаются с нулевыми счётчиками.

Ответ `status` объявляет capabilities `install-step-progress` и `dns-settings`.
`get_settings` дополнительно определяет текущее состояние DNS существующим device helper.
`set_settings` принимает только HTTPS URL и `dns_enabled` (boolean либо null).
Выбор сохраняется в `settings.json` и применяется при следующей установке, после APK,
перед sync/reboot. Null означает сохранить текущий DNS. Для старых settings это значение
по умолчанию. Изменение одного DNS не сбрасывает проверенный скачанный архив.

Если DNS управляется VoyahTune, исходное состояние переключателя соответствует текущему
DNS, пока пользователь не сохранил другой выбор. Включение при стандартном DNS выполняет
`install`, выключение при Яндекс DNS — `disable` существующего helper, возвращая штатные
ресурсы после reboot. Совпадающий выбор сохраняет текущую настройку без перезаписи.
Внешний, повреждённый или неизвестный DNS не заменяется: переключатель недоступен;
ошибка настройки DNS записывается в журнал и не прерывает установку релиза.
Это состояние статического DNS-overlay, не измерение DNS-ответов сети.

Helper встроен в executable из `Packaging/installer/common/dns-overlay-device.sh`;
пользователь не передаёт произвольный script/path. Перед изменениями проверяются доступ
к /vendor и закреплённый SHA-256 DNS APK. Общий mutex вызова системных команд защищает
`command.log` при одновременных запросах настроек и фоновой работе. Настройка во время
операции запрещена. IPC команды настроек допускают более долгий ответ, чем обычный status.

Эти изменения требуют нового root executable и APK через USB. Самообновление updater
по OTA по-прежнему исключено. Исполняемый desktop и его ресурсы не менялись: для этой
задачи достаточно новых APK/daemon и payload; пересборка desktop не требуется.
Локальные тесты и сборки не подтверждают DNS и отображение на OEM ГУ.


## Нативный интерфейс

Android UI использует XML-компоновку с боковыми этапами, компактной карточкой релиза,
верхним информационным блоком, закреплённой строкой действий и диалогом настроек.
Отступы под Qinggan dock и системную панель сохранены. Дерево View создаётся один раз.
Опрос раз в две секунды обновляет только изменившиеся тексты, значения и видимость;
сам status-запрос не отключает кнопки и не сбрасывает фокус или прокрутку.
Блокировка действий зависит от текущей операции и явно отправленной команды.

Проверка архива, подготовка, reboot и проверка запуска используют неопределённый
индикатор. При установке используется счётчик успешно завершённых групп из root-службы.
Старая служба без счётчиков показывает неопределённый прогресс; отсутствие capability
DNS отключает переключатель с пояснением про USB-обновление службы. При потере связи
действия установки недоступны, прежний успех не выдаётся за актуальное состояние.
Ошибку предварительной проверки можно исправить и повторить установку сохранённого
архива; `repair-required` требует USB.

Согласованный дизайн реализован нативными Android View, без WebView и демонстрационных
таймеров. 5 JVM-тестов проверяют отображение фаз и достоверность прогресса. Debug/release
APK собираются локально. Визуальная проверка Android-компоновки и DNS на ГУ ещё не
выполнялась; установленного системного образа Android-эмулятора в этом окружении нет.

## Интеграционные проверки без автомобиля

Внешний интерфейс UI → root — `UpdateService.call(JSONObject)`; production-адаптер
`RootClient` сохраняет JSON schema 1, framing, ограничения размера и проверку peer UID.
В instrumentation используется настоящий LocalSocket с mock root-службой.
`VehiclePort` отделяет запросы/события автомобиля от контроллеров Native; production
использует прежние OEM session и CanBusEventHub. Stateful mock возвращает чтения,
принимает или отклоняет записи, выдаёт отложенные события и имитирует потерю связи.
Отправка команды и подтверждение состояния проверяются раздельно.

| Набор | Что проверяется |
| --- | --- |
| OTA, 12 сценариев | Фазы от idle до committed/repair-required, прогресс, подтверждение apply, настройки, legacy finish, ошибочные ответы, peer UID, разрыв/возврат связи и повторное открытие UI |
| Native, 9 сценариев | Настоящий Binder-декодер с mock RestoreMode под отдельным UID, аргументы команд/Parcelable, ответы apply/cleanup, подписки и владельцы, энергия/подвеска, таймаут и отказ автомобиля, P/SOC Power Hold, голосовой session gate и OEM transport, чтение/запись mock ContentProvider |
| RestoreMode, 8 сценариев | Настоящие Activity с mock Native под отдельным UID: команды, callbacks в виджеты, несовместимая schema, Apply до ответа, pause/resume/recreation, смерть сервиса/rebind, настоящий ContentProvider, broadcast сплита и полная цепочка с Native + mock автомобиля |

Mock-компоненты находятся только в `src/debug` и `src/androidTest`. Release APK не
содержит mock сервисов, тестовых Activity или выбора тестового endpoint через Intent.
Android-операции вроде reboot, overlay и запуска приложений подменены на границе
обработчика; это проверка маршрутизации, не фактического действия Android/OEM.
Симулятор не моделирует весь CAN-протокол и не заменяет приёмку датчиков/исполнителей,
init, SELinux, питания и PackageManager на Android 11 ГУ.

После запуска Android-эмулятора, с настроенными JAVA_HOME/ANDROID_HOME:

```sh
python3 Utils/test_android_integration.py --serial emulator-5554
python3 Utils/test_ota_process_isolation.py --serial emulator-5554
```

Первый скрипт собирает debug APK и JVM-тесты, устанавливает Native первым (владелец
signature permission), затем остальные APK, запускает три набора. `--suite native`,
`--suite restore`, `--suite ota` выбирают наборы; `--no-build` использует готовые APK.
Второй тест требует root-доступ на эмуляторе, проверяет реальную `OtaActivity` при
блокировке рабочего процесса и удаляет только созданный им блок в `finally`.
Оба скрипта запрещают запуск на физическом устройстве. Эмулятор должен быть тестовым:
наборы заменяют debug APK и настройки mock-сценариев. Фактически проверено на AAOS 13 ARM64.

## Произвольный каталог и beta

URL на экране настроек остаётся доступным; «По умолчанию» подставляет адрес из
`settings.defaultCatalogUrl`. Сохранение последовательно вызывает `set_settings`,
затем `check`; для прежней службы поддерживается `set_catalog_url`.

`state.catalogVersions` содержит доступные версии последнего прочитанного каталога,
`selected` — выбранный релиз. При смене URL и перед новой проверкой список очищается
вместе с прежним выбором, notice и ошибкой. Пустой массив означает отсутствие
подходящих версий; отсутствующее поле — ещё не полученный результат.

Beta сравнивается с `minimumOtaVersion` по базовому номеру установленного VoyahTune;
порядок доступных релизов учитывает полный SemVer. Смена источника не обновляет
root-службу и не отменяет необходимость USB при несовместимом исполнителе.

## Каталог API, выбор версии и журналы OTA

Единая служба по умолчанию получает каталог через `GET https://voyahtune.ru/api/v1/releases`.
Архив загружается по `url` выбранной записи (`/api/v1/releases/:id/download`).
Сохранённые прежние стандартные GitHub/GitLab URL мигрируют на API; собственный URL и beta
сохраняются.

Capability `select-release` открывает выбор доступной единой версии из последнего каталога.
Повторная установка и выбор более старой версии разрешены; `pm install -r -d` передаёт
операцию Android PackageManager. `minimumOtaVersion` проверяется при подборе, ручном
выборе, скачивании и применении, включая переустановку. Если установленная базовая
версия ниже минимума или минимум отсутствует, требуется USB. `minimumInstallerVersion` относится к компьютерному установщику. Это единственная проверка допуска к OTA: размер/SHA-256 архива, подписи APK, совпадение метаданных и capabilities не ограничивают установку. Ошибки распаковки, записи и запуска обрабатываются отдельно.
Релиз, требующий USB, не подменяется более старым. По умолчанию предлагается самая
новая запись; автоматическая проверка не прерывает активную операцию.

Новая служба доставляется через USB в payload. Обычное OTA не заменяет собственный
executable, поэтому существующие установки начнут использовать эти правила после USB.

Сессия начинается при подтверждении загрузки, продолжается через применение и
проверку запуска после reboot. Повторная попытка после ошибки получает новый ID.
Журналы хранятся в `/data/local/voyahtune-updater/installation-sessions/<sessionId>/`:
`session.json`, `logs.jsonl`, `chunks/*.json`. Каждый снимок содержит `isOta: true`.
Шаги, ошибки команд и logcat отправляются по 100 событий; если JSON приближается
к 1 МиБ, чанк формируется раньше. Слишком большие данные события разбиваются на
`encodedDataFragment` с `fragmentIndex`/`fragmentCount`, без потери содержимого.

Перед reboot остаток сохраняется с `finalChunk: true`, но статусом `in_progress`.
Рабочий поток посылает сигнал фоновому журналу и ждёт результата одной попытки
отправки текущего чанка (HTTP timeout 10 секунд). При ошибке пакет остаётся на диске,
повторной отправки нет, пакет доступен только локально.
После запуска сохраняются sessionId и сквозные sequence/chunkIndex, продолжается
сбор только новых значимых событий logcat без накопленного буфера Android. Успех подтверждается только после
проверки запуска; ошибка или прерывание установки завершают сессию с `finalReason`.

Отправитель использует `POST /api/v1/installation_log_chunks`: по контракту этот
запрос также создаёт сессию. Каждый новый чанк отправляется один раз.
При сетевой ошибке или HTTP-отказе пакет остаётся только локально, без ретраев
и без досылки после reboot. Принятые пакеты помечаются `.sent`.
Смена выбранного релиза/источника либо явное завершение подготовки закрывает старую
сессию. Обычная запись шага/ошибки только ставит событие в очередь. Фоновый журнал
единолично выполняет дисковый ввод-вывод, нарезку и финализацию; отдельные потоки
собирают logcat и выполняют HTTP. Очередь logcat ограничена 512 элементами: при
задержке диска ждёт только сборщик, а не установка и IPC-интерфейс.

Перед созданием новой сессии фоновый журнал удаляет все предыдущие каталоги сессий,
включая локальные события, принятые и ещё не отправленные чанки, а также старые
`updater.log`/`updater.log.1`. Продолжение активной сессии и reboot не запускают очистку.

Изменения службы требуют нового payload и установки через USB. Пересборка GUI
нужна только при изменении его кода, ресурсов или контракта; обычная OTA не заменяет бинарник службы. Локальные проверки не заменяют испытание на ГУ.
