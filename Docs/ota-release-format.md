# Формат каталога OTA

Установщик и OD root-служба по умолчанию читают
[Releases/ota/index-v4.json](../Releases/ota/index-v4.json) для релизов **4.0.0 и новее**.
Каталог пока пуст: запись добавляется после подготовки и публикации реального архива.
Базовые версии — Installer **1.6.0** и payload **4.0.0-od**.
Прежние `index.json` и `index-beta.json` сохраняются без изменений. PI сохраняет прежний адрес.
Старый [Installer/releases/index.json](../Installer/releases/index.json) остаётся для
прежних установщиков; новые релизы в него не добавляются.

Адрес по умолчанию:

```text
https://gitlab.com/openvoyah/voyahtune/-/raw/master/Releases/ota/index-v4.json
```

В установщике и root-службе адрес изменяется через настройки и сохраняется между запусками.
Обновление приложения не заменяет ранее сохранённый адрес. Кэш установщика разделён по URL.
Каталог можно разместить на любом доступном HTTPS-хосте. Прежний формат остаётся совместимым:

```json
{
  "releases": [
    {
      "version": "3.15.0",
      "url": "https://storage.yandexcloud.net/voyahtune/payload_3.15.0.zip",
      "size": 149407190,
      "sha256": "92347612bec3e147d4bf54aee0f4f08e9646fe219ba2c47605367faa6827d84d"
    }
  ]
}
```

Это параметры ранее загруженного архива, а не новой сборки с изменённой службой.
Новая сборка получает собственные размер и SHA-256; их нельзя переносить со старой.

У записи есть четыре поля архива и два дополнительных ограничения совместимости.
Для `index-v4.json` оба ограничения обязательны; старые каталоги читаются без них.
Фрагмент первой записи (URL, размер и SHA-256 добавляются из настоящего архива):

```json
{
  "version": "4.0.0-od",
  "minimumInstallerVersion": "1.6.0",
  "minimumOtaVersion": "4.0.0"
}
```

`minimumInstallerVersion` — минимальная версия GUI. При выборе релиза более старый
установщик показывает ошибку с просьбой скачать эту версию или новее. Проверка выполняется
до скачивания и при выборе локально сохранённого релиза из каталога. Проверки manifest
после скачивания сохраняются и могут предъявлять более строгие требования.

`minimumOtaVersion` — минимальная **установленная версия VoyahTune** для OD OTA.
Например, у `4.1.0-od` с новой root-службой указывают `4.1.0`: автомобиль с `4.0.0-od`
получит ошибку с предложением USB-установки через Installer версии `minimumInstallerVersion`
или новее. Несовместимый свежий релиз не подменяется более старым OTA-релизом.
Ограничение повторно проверяется перед скачиванием и применением, включая сохранённый выбор.
Для PI новое ограничение OTA не применяется.

Минимумы записываются как `major.minor.patch`, без суффиксов. Сравнение идёт по SemVer:
`1.10.0 > 1.7.0`; установленная `4.1.0-od` удовлетворяет минимуму `4.1.0`,
а `4.1.0-beta-od` — ещё нет. `minimumOtaVersion` требует наличия `minimumInstallerVersion`.
Клиенты, выпущенные до поддержки этих полей, не умеют показывать новые сообщения:
первое внедрение обновлённой root-службы выполняется через USB.

Отдельных metadata, signature, ключа OTA,
маркера доступности, sequence, даты публикации и вложенного payload нет.
Каталог перечисляет доступные новым клиентам релизы. Порядок выбора определяется
SemVer, а не порядком строк. Обычный список GUI и OTA выбирают стабильные версии; prerelease проверяют локальным импортом.
Повторная версия в каталоге, некорректный SHA-256, нулевой/слишком большой размер,
неизвестные поля и URL без HTTPS отклоняются.

HTTPS-каталог — доверенный источник URL и контрольной суммы. Размер/SHA-256
проверяют полученные байты; отдельного подтверждения издателя каталога нет.
После скачивания проверяются манифест, поддержка схемы/recipe/capabilities,
требования к установщику, целостность файлов и подписи APK. Перед OTA проверяются
совпадение подписей с установленными APK, исходная OEM-прошивка и неизменность
самой службы/boot-контракта. Несовместимый релиз не применяется.
Каталог задаёт предварительные ограничения; требования внутри архива проверяются независимо.

`./make_release.sh VERSION --payload` создаёт ZIP и готовую плоскую запись
`Releases/dist/payload_VERSION.json`, где VERSION включает `-pi`/`-od`. Подписывать её не нужно.
Для OD 4+ генератор берёт `minimumInstallerVersion` из manifest и записывает
`minimumOtaVersion: "4.0.0"`. При изменении root-службы явно передавайте новый минимум,
например `--minimum-ota-version 4.1.0`. Для PI и прежних релизов формат записи не меняется.
При обновлении каталога явно задавайте `--index Releases/ota/index-v4.json`;
скрипт отклоняет версии ниже 4 и записи без минимумов до обращения к сети.
Локальная проверка каталога без сети:

```sh
Installer/target/release/installer-build verify-catalog Releases/ota/index-v4.json
```

Проверка версии/манифеста/APK распакованного релиза:

```sh
Installer/target/release/installer-build verify-ota ENTRY_JSON PAYLOAD_DIRECTORY
```

Эта команда не скачивает ZIP и не проверяет его размер/SHA-256: это выполняют
клиенты при скачивании и скрипт публикации. Порядок публикации — в
[инструкции выпуска](releasing.md). В Git хранятся `Releases/ota/index.json`,
`Releases/ota/index-beta.json` и `Releases/ota/index-v4.json`;
остальные сборочные файлы в `Releases/` остаются игнорируемыми.

Обновление на более старую версию запрещено. Повтор той же версии разрешается
отдельной тестовой кнопкой; после успешной OTA допускается только тот же SHA-256.
В Android `versionCode = major × 1000000 + minor × 1000 + patch` (компоненты 0–999).
