# Формат каталога OTA

Компьютерный установщик и единая root-служба по умолчанию получают каталог через:

```text
https://voyahtune.ru/api/v1/releases
```

URL архива берётся из поля `url` записи (`/api/v1/releases/:id/download` у backend);
идентификатор не вычисляется из номера версии. Пользовательский HTTPS-источник
сохраняется между запусками. Прежние стандартные адреса мигрируют на API, собственные
адреса и beta сохраняются. Кэш GUI разделён по URL; ошибка сети допускает показ
только копии того же источника с предупреждением.

Каталог обслуживается сервером. Локальные JSON-индексы больше не ведутся.
Сборочный `payload_VERSION.json` описывает конкретный архив и не является
публичным каталогом. Сборка и появление релиза в API — отдельные действия.

## Поля записи

Каталог — объект `releases[]`. Запись содержит:

| Поле | Смысл |
| --- | --- |
| `version` | Единая SemVer-версия, например `4.5.0` или `4.5.0-beta` |
| `url` | Публичный HTTPS-адрес архива |
| `size` | Размер готового ZIP в байтах |
| `sha256` | SHA-256 точных байтов ZIP |
| `minimumInstallerVersion` | Минимальная версия компьютерного установщика |
| `minimumOtaVersion` | Минимальная установленная версия VoyahTune с совместимой root-службой |

Для новых единых релизов указываются оба минимума. Пример фрагмента первого единого
релиза с новой службой; URL, размер и SHA-256 добавляются из настоящего архива:

```json
{
  "version": "4.5.0",
  "minimumInstallerVersion": "1.8.1",
  "minimumOtaVersion": "4.5.0"
}
```

Номер в примере условный. Размер и хеш нельзя переносить с другого архива.
Каталог не содержит отдельной подписи OTA, sequence, вложенного payload или списка
установщиков. Повторная версия, некорректный SHA-256, недопустимый размер, неизвестные
поля и URL без HTTPS отклоняются. Поддержка старых записей без минимумов сохраняется
для старых каталогов, но не является шаблоном нового выпуска.

## Совместимость и выбор

`minimumInstallerVersion` проверяется до скачивания и при выборе кэшированного
релиза из каталога. После скачивания независимо проверяются manifest, схема,
recipe, capabilities, файлы и подписи APK. Текущий единый контракт требует
Installer 1.8.1 с `unified-runtime-v1`.

`minimumOtaVersion` определяется совместимостью root-службы. Если новая служба
впервые поставляется в `4.5.0`, этот минимум требует первоначальную USB-установку.
При следующих совместимых релизах он сохраняется. Новый номер GUI сам по себе
его не повышает. Проверка выполняется при выборе, скачивании и применении,
включая сохранённый выбор. Релиз, требующий USB, не подменяется более старым.

Минимумы имеют вид `major.minor.patch`. Версия установленного VoyahTune сравнивается
по базовому номеру: `4.5.0-beta` удовлетворяет минимуму службы `4.5.0`.
Порядок самих релизов определяется полным SemVer: stable выше beta того же номера.
Единая служба выбирает версии без инфраструктурных суффиксов, включая prerelease,
если они присутствуют в выбранном каталоге. GUI может показывать и исторические записи.

По умолчанию предлагается новая запись по SemVer. Capability `select-release`
позволяет явно выбрать доступную версию, включая повторную установку или откат;
автоматическая проверка не начинает установку и не прерывает активную операцию.
Ограничения совместимости сохраняются и при ручном выборе.
После ошибки сети UI показывает ошибку, а не отсутствие обновлений. Смена URL
и новая проверка очищают прежний выбор и результаты; скачивание и установка
остаются отдельными действиями.

HTTPS-каталог является доверенным источником URL и контрольной суммы. Размер и
SHA-256 проверяют полученные байты, но не являются отдельной подписью издателя.
Содержимое скачанного payload проверяется до применения. Фактические проверки
перед записью и после перезагрузки описаны в [рабочем цикле службы](ota-updater.md#рабочий-цикл).
Собственный бинарник root-службы обновляется через USB.

## Подготовка и проверка

```sh
./make_release.sh 4.5.0 --payload --minimum-ota-version 4.5.0
```

Сборщик создаёт `Releases/dist/payload_4.5.0.zip` и плоскую запись
`payload_4.5.0.json`. Минимум Installer берётся из manifest; минимум OTA задаётся
явно на основании совместимости службы. Для последующего совместимого релиза
сохраняйте прежний подтверждённый минимум.

Проверка записи и распакованного payload без сети:

```sh
Installer/target/release/installer-build verify-ota ENTRY_JSON PAYLOAD_DIRECTORY
```

`verify-ota` проверяет распакованный payload, а не размер/SHA-256 удалённого ZIP.
Скачивание и проверку архива выполняют клиенты. Изменение локального JSON не
регистрирует релиз в API. [Подготовка выпуска](releasing.md).

В Android `versionCode = major × 1000000 + minor × 1000 + patch` (компоненты 0–999).
Beta-суффикс не меняет это значение. RunYN имеет собственный номер приложения;
его состав и условие установки описаны в [контракте payload](installer-payload.md).
