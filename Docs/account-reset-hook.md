# Подстраховка восстановления при событиях аккаунта Sport+

Описание относится к инфраструктуре **OD** (`Packaging/od/`); перенос этих hooks
в PI не подразумевается. [Разделение релизов](installer-payload.md).

В релиз входит `Packaging/od/inject/voyahtune_drive_reset.js` для процесса
`com.qinggan.app.vehiclesetting`. Он ограничен H97X (`AppCommonUtils.is97X()`) и
двумя методами `VehicleMemoryManager` из VehicleSettings Sport+ 13.1:

- `resetSettings()` — выход из аккаунта с переходом в гостя;
- `resetOverseaDriveMode()` — вход на экспортной машине, включая тот же аккаунт.

У `resetSettings()` есть дополнительные действия с рекуперацией, подсветкой и
удержанием режима, поэтому оригинальный метод сохраняется. Java `ThreadLocal`
ограничивает подмену его вызовом: хук копирует исходящий `vehicleBundle` перед
`CanBusManager.setVehicleAndAirConditionBundleState` и изменяет только выбранные
поля. Setter вызывается ровно один раз. Результат и исключения передаются без
повторной отправки. Другие потоки и вызовы вне этих методов не затрагиваются.

При каждом сбросе читается свежий снимок из провайдера VoyahTune:

| Настройка | Поведение |
| --- | --- |
| Вождение, если восстановление включено | Подставляются `DRIVING_MODE_SET`, `EPS_MODE_SET`, `PROP_MODE_SET` |
| Individual | Руль и педаль берутся из OEM Global settings аккаунта, определённого штатным `Utils.getAccountId()` |
| Энергия, если восстановление включено | `IVI_SOC_MODESET`: SMART=1, EV=2, REV=3, SREV=4 |
| Forced EV | Значение 5 имеет приоритет независимо от включения обычного энергорежима |
| Сервисный режим подвески | Всегда сохраняемый `ASC_MAINTAIN_SWITCH`: включён=2, выключен=1 |

Отключённые режимы вождения/энергии остаются штатными. Рекуперация отдельно
не восстанавливается. Для выбранного Snow поле высокой рекуперации из сброса
удаляется: уровень задаёт OEM-обработчик Snow, как и при восстановлении Native.
Подсветка и остальные поля исходного пакета сохраняются.

Если provider недоступен, снимок неполон, включена отладка или выбранное значение
не удалось проверить, используется исходный пакет. Отсутствующие OEM-ключи
Individual дают штатные значения руль=2, педаль=1; ошибка доступа к provider
отсутствием ключа не считается. Хук не записывает настройки и не запускает
полное восстановление Native.

`load.bin` загружает хук независимо от переключателя Apollo, но последовательно
с Apollo в одном worker, без одновременных инъекций в один процесс. На идентичность
процесса даётся одна попытка с обязательным ready-marker. Новый PID/starttime
допускает новую попытку, перезапуск загрузчика не дублирует действующий хук.
Частичная установка методов откатывается.

Установщики и GUI включают скрипт. Удаление очищают файл,
маркеры и журнал. Диагностика: `VoyahDriveReset`, `[drive-reset] hook ready v1`,
`/data/local/tmp/voyahtune_drive_reset.txt`.

Первый вызов при холодном старте может опередить Frida attach. Дополнительная
стартовая отправка режимов и однократный проход остальных настроек Native
привязаны к ACC-циклу. Прямой ACC ON сброс
в отдельном CanBusService перехватывает отдельный приоритетный агент, описанный в
[acc-restore-hook.md](acc-restore-hook.md). Принятие запроса не
подтверждает физическое применение. На автомобиле хук ещё не проверен.
