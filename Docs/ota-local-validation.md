# Локальная подготовка OTA к приёмке — 2026-09-28

Исходники установки/службы: коммит `ba453f4` ветки `ota-update`. VoyahTune 3.15.0,
Installer 1.2.0, updater 0.1.0. Исправление упаковки — `2d5edf6`. APK metadata schema 3, payload schema 4, recipe schema 3.
Это результаты локальных проверок, не допуск к массовому выпуску и не испытание ГУ.

## Выполненные проверки

- Rust workspace: 29 тестов, последовательно; root-служба: 10 тестов.
  Сетевой fixture запускается вне sandbox, так как ему нужен локальный TCP-сокет.
- Native и RestoreMode: JVM-тесты и debug-сборки на этапе интеграции.
  После переноса блокировки запуска в attachBaseContext финальные release APK
  пересобраны общей командой сборки payload.
- Updater: debug/release APK и ARM64 executable; итоговый payload содержит 28 артефактов.
- Svelte: check/build без ошибок; сборка GUI использует общий Rust-движок.
- Fake ADB: 10 сценариев, включая USB-установку OTA bootstrap поверх приложений,
  сохранение данных, выгрузку диагностики прерванной OTA, удаление и отказ при занятом lock.
- OTA-подпись: проверка финальных APK/manifest/recipe, реальных package ID/versionCode,
  отказ при подмене подписанного тела и привязки к архиву. Тест использует отдельный
  временный RSA-ключ; ключ релизов в тестовые данные не попадает.
- Публикация каталога: пять тестов. Подписанный кандидат общего index прошёл verifier.
- Инсталляторы macOS Universal, Windows x64, Linux x64 собраны с payload 3.15.0.
  macOS: verifier проверил ресурсы внутри .app; Windows: проверка 7z архива NSIS.
  Linux: .run извлечён, вложенные ADB/remover/payload повторно прошли verifier.
- Локальные Markdown-ссылки и git diff --check.

Первая попытка Linux-сборки прошла Svelte check, но упала внутри Go runtime esbuild
под эмуляцией x64. В оркестраторе общий web-интерфейс перенесён на нативную сборку
macOS; контейнеры получают свежий dist, затем собирают Rust и пакеты. Это изменение
сборочного процесса, а не поведения OTA на ГУ. При упаковке дополнительно заменены
статические patchelf/strip извлечённого linuxdeploy на системные динамические
инструменты подготовленного контейнера; первоначальный сбой обработки библиотек
не игнорировался.

## Ограничения

Запуск приложений Windows/Linux на пользовательской ОС не проверялся. Сборка пакета
не заменяет UI-проверку на каждой платформе. Нет подключения к автомобилю, реальной
USB/OTA-установки, публикации архива или изменения публичного каталога.
OEM init/SELinux/IPC, HTTPS с ГУ, remount, PackageManager, питание и сохранность
настроек проверяются по [шести этапам приёмки](ota-acceptance.md).

Автоматический интервал между холодными загрузками опирается на системные часы;
время ГУ и сон/пробуждение необходимо проверить. Дополнительные функции и hooks
сторонних приложений требуют ручной финальной проверки; служба подтверждает запуск
основных компонентов и наблюдаемые статусы, а не каждую функцию автомобиля.
