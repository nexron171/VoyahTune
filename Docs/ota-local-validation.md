## Ограничения

Запуск приложений Windows/Linux на пользовательской ОС не проверялся. Сборка пакета
не заменяет UI-проверку на каждой платформе. Нет подключения к автомобилю, реальной
USB/OTA-установки, публикации архива или изменения публичного каталога.
OEM init/SELinux/IPC, HTTPS с ГУ, remount, PackageManager, питание и сохранность
настроек проверяются по [шести этапам приёмки](ota-acceptance.md).

Автоматический интервал между холодными загрузками опирается на системные часы;
время ГУ и сон/пробуждение необходимо проверить. Дополнительные функции и hooks
сторонних приложений требуют ручной финальной проверки; служба подтверждает запуск
основных компонентов и наблюдаемые статусы, а не каждую функцию автомобиля.

## Первая живая проверка: серый экран Updater

2026-09-28, официальная ROM Android 11 build 650, payload 3.15.0 из `ffa87a1`.
Root-служба стартовала и прочитала новый каталог. При открытии UI Android оставлял
Splash Screen: процесса Updater не было, Activity оставалась INITIALIZING, ANR отсутствовал.
При повторном запуске logcat показал fatal Zygote: невозможно смонтировать
`/data_mirror/data_de/null/0/ru.big.town.updater` — DE-каталог отсутствует.

Переактивация системного пакета через `pm uninstall -k --user 0` и
`cmd package install-existing --user 0 --wait` создала CE/DE через PackageManager,
с сохранившимся UID и без очистки данных. После этого `am start -W` завершился
`Status: ok`, интерфейс отрисовался. Это подтверждение восстановления запуска,
а не успешной установки OTA.

В открывшемся интерфейсе выявлена отдельная ошибка `socket not created`: LocalSocket
получал setSoTimeout до connect. Также OEM-док перекрывал левую часть содержимого.
На момент первой проверки эти ошибки требовали исправления APK.

## Проверка скачивания для повторной установки

2026-09-28 на том же ГУ через интерфейс выбрана повторная установка 3.15.0 и нажато
«Скачать». Root-служба скачала 149372721 байт примерно за 17 секунд. SHA-256 файла
совпал с каталогом: `a56e4b729e7fa6087e8783c57189facb347bc794a0580977d6c6bc6e844cf686`.
В UI отображался прогресс; распаковка завершилась (28 записей).

Последующая проверка совместимости завершилась ошибкой
`voyahtune-updater.apk требует установки через USB`: опубликованный архив содержит
прежний Updater, а на ГУ уже установлен исправленный APK. Текущая реализация
`install::compatible` требует совпадения инфраструктуры OTA с установленной.
Это отказ совместимости после успешной загрузки, а не сетевая ошибка. UI показал
причину; кнопка установки осталась недоступной. Применение релиза и перезагрузка
не запускались. Для продолжения приёмки нужен согласованный payload либо отдельно
согласованное изменение правил обновления Updater.
