# Восстановление режимов вождения и двигателя

Режимы восстанавливаются через перехваты известных OEM-сбросов и дополнительную
стартовую команду после готовности CAN-компонента и настроек. `EarlyDriveModeRestore`
и его 30-секундное окно удалены. Остальные настройки Native применяет один раз
в том же сохранённом ACC-цикле; автоматический `CanRestorePlan` исключает профиль
вождения и энергорежим. Дверь и первый D не запускают применение.
Ручное «Применить» по-прежнему включает выбранные режимы.

## Источник команды

Гостевой сброс в `onBCM_PEPSChangeData`, `VehicleMemoryManager.resetSettings` и
`resetOverseaDriveMode` подменяются актуальными целями. Входы штатного экрана
`DrivePreferenceFragment.setDriveMode(int)` и `setPowerMode(int)` маркируют только
исходящие из их вызовов пакеты. Ранний отказ UI без отправки не сохраняет выбор.
Переключатель Forced EV обрабатывается в контексте `onHintSwitchClick` и реально
вызванного одиночного setter. Intent-сервис сам по себе не считается ручным источником.

CAN-агент распознаёт команды Native и маркированные пакеты VehicleSettings, убирает
служебные поля перед OEM-преобразованием Bundle и сохраняет намерение через provider.
Обычный `DRIVING_MODE_SET` или `IVI_SOC_MODESET` feedback обновляет наблюдаемое состояние,
но не сохранённый выбор. Неизвестные команды проходят без коррекции.

Для кнопки салона добавлен отдельный перехват в `com.qinggan.app.vehicle` (VehicleAir).
Он ограничивает пользовательский контекст обработчиком `SET_DRIVE_MODE=3` в
`DriveModeViewManager$1.handleMessage` и подтверждением Eco в `$2.onClick`.
После возврата 0 из `CanBusManager.setVehicleAndAirConditionBundleState` сохраняет
профиль напрямую через `driveHookV2 user`; это успешный возврат IPC-обёртки,
не подтверждение выполнения автомобилем. Второй пакет EPS/PROP ничего не сохраняет.
Автоматический вызов `setDriveMode(2)` при выходе из Outing по скорости вне этих
обработчиков не запоминается. Ошибка provider не повторяет OEM-команду.
Подробности исследованного APK — в [разборе кнопок салона](cabin-buttons.md#установленный-отправитель-кнопки-vehicleair).
Provider уведомляет открытые настройки через `MODE_SYNCED`; при выключенном
запоминании селектор продолжает показывать фиксированную настройку.

## Состояние и старт

`DrivePreferences` хранит сохранённые настройки, `currentTripDrive`, `currentTripEnergy`,
номер цикла/изменения цели и состояние стартовой операции. Provider `driveHookV2`
сериализует изменения и записывает их через `commit`, поэтому перезапуск Native или
агента не обнуляет текущий выбор. Начало нового цикла определяется наблюдением ACC
CAN-агентом; новая загрузка Android также создаёт новую границу. Один только экран,
дверь, передача или переподключение Native её не создают.

При выключенном запоминании обычный ручной выбор действует в текущем цикле, а
на следующем возвращается сохранённая настройка. При включённом — обновляет её.
[Приоритет виджета подвески](suspension-widget.md#приоритет-режима-и-история-средней-высоты)
сохраняется отдельно до следующего подтверждённого выбора другим способом.
Forced EV остаётся отдельным флагом и не заменяет сохранённый обычный энергорежим.

После установки перехватов агент обнаруживает живой CAN-компонент и отправляет
один дополнительный пакет разрешённых режимов. При неготовности компонента/provider
повторяется проверка готовности через 5 секунд. Это не проверка отличия режимов:
наблюдаемое значение не сравнивается с целью и не вызывает исправления.
После устойчивого захвата стартовой операции повторной отправки в том же цикле нет.
Неоднозначный отказ отправки оставляет `uncertain`, без слепого повтора.

Пользовательский выбор вождения или энергии переводит стартовую операцию в
`selected` и повышает ревизию. Ожидающая стартовая отправка отменяется, включая
перезапуск агента; старый `complete` не перезаписывает новое состояние. Новый цикл
ACC снова разрешает стартовую операцию. Уже начатую отправку отменить этим нельзя.

Состояния `pending`, `claimed`, `submitted`, `uncertain`, `selected` описывают отправку/её отмену, а не
физическое выполнение. В очередь передаётся метка происхождения для диагностики.
После штатного обработчика ACC агент также вызывает Native для одного прохода
остальных настроек. Provider сохраняет для него отдельное состояние `settingsStartup`:
`pending` → `claimed` → `submitted` либо `uncertain`. Native проверяет его при
каждом запуске сервиса; повторное уведомление не создаёт второй проход. При позднем
attach или временном отказе запуска Native агент снова инициирует проверку через
5 секунд. Эта отметка означает приём плана, а не
физическое подтверждение. Ручное «Применить» остаётся отдельным действием.
Если Native завершится после `claimed`, но до записи результата, слепого повтора
не будет: следующий ACC-цикл создаст новую попытку.

Уже принятый пакет не сравнивается с новой целью и не переписывается на выходе;
короткая гонка с последующей командой допускается. Последующий известный системный
сброс читает актуальную цель текущего цикла.

## Ограничения и проверка

Исследованы H97X CAN-служба, VehicleSettings Sport+ 13.1 и VehicleAir с автомобиля
(хеш приведён в разборе кнопок). Совместимость других
прошивок подтверждается отдельно. При позднем подключении неизвестный ручной выбор,
сделанный до перехватов, нельзя отличить от автоматического. Дополнительная стартовая
команда не устраняет эту неоднозначность. При отключении восстановления соответствующее
поле не добавляется в стартовый пакет; debug сохраняет штатное поведение.

JVM-тесты проверяют политику выбора и сохранение настроек. JS-тесты проверяют источники,
подмену пакетов, отсутствие повторной стартовой отправки и сохранение OEM-обработки.
Локальные тесты не заменяют испытания гостевого ACC и физической кнопки на машине.
Диагностика и восстановление агента описаны в [ACC-хуке](acc-restore-hook.md).
