# Диспетчер задач

Отдельный экран со списком запущенных сторонних приложений. Открывается двумя способами: коротким
нажатием на плитку «Диспетчер задач» 1×1 на главном экране и долгим нажатием на нижнюю кнопку родного
дока («Все приложения») в Full-сборке. Раньше долгое нажатие этой кнопки открывало главный экран
VoyahTune.

Плитка включается в «Дополнительно» → «Главный экран» («Диспетчер задач», по умолчанию включена),
занимает одну ячейку и показывает в центре число запущенных приложений. Число приходит ответом Native
на запрос плитки при отрисовке главного экрана и при подключении к сервису, поэтому после возврата из
диспетчера оно актуально; отдельного периодического опроса нет.

## Экран и карточки

В ряд помещается шесть слотов: пять карточек приложений и карточка «Закрыть все приложения».
Приложений больше — ряд прокручивается горизонтально, и «Закрыть все» уезжает в конец списка. Карточка
приложения: булавка фиксации, иконка (нажатие выводит задачу приложения на передний план), имя
приложения и кнопка «Закрыть» в стиле виджета приложения на главном экране. Приложение, запущенное
внутри виджета, получает тот же вид плюс бейдж «в виджете» — по нему видно, что копия живёт в
VirtualDisplay виджета, а не на экране. Без запущенных приложений карточка «Закрыть все» не
показывается, а по центру выводится «Нет запущенных приложений».

Слева остаётся полоса родного дока (145 dp), поэтому хук лаунчера обязан удерживать док и над этим
экраном — `TaskManagerActivity` добавлена в `ourInsetActivity` в `launcherdock.js`. Полоса дока
резервируется сразу в `onCreate` (`root.setPadding(...)`), а системные отступы добавляются из
`setOnApplyWindowInsetsListener`; для этого экран обязан вызывать `EdgeToEdge.enable(this)` до
`setContentView` — иначе платформа сама поглощает insets, слушатель у контента не срабатывает и левый
край экрана уходит под док (проверено на машине). Экран выходит по системной кнопке «Назад», кнопке «×»
в заголовке или после нажатия «Закрыть все приложения»: в последнем случае диспетчер закрывается и
возвращает на предыдущий экран.

## Отбор и действия

Список и действия выполняет Native: у RestoreMode нет `REAL_GET_TASKS`, а закрытие требует
`FORCE_STOP_PACKAGES`. Используется тот же отбор, что и в «Закрыть приложения» (`WidgetSupport.isExternal`):
только сторонние приложения, исключены системные, вендорские `com.qinggan.*`/`com.android.car.*`, сам
VoyahTune, Native и штатный лаунчер; контакты и штатный телефон исключением не являются.

| Действие | Что делает Native |
| --- | --- |
| Список | `ActivityManager.getRunningTasks(100)`, дедупликация по пакету, подпись из `PackageManager` |
| «Закрыть» на карточке | снятие виджетов этого приложения, затем `forceStopPackage`; список перечитывается после паузы 600 мс |
| «Закрыть все приложения» | существующий `MSG_CLOSE_ALL` (тот же путь, что у кнопки в «Дополнительно») |
| Нажатие на иконку | `moveTaskToFront` для первой задачи пакета; для приложения внутри виджета — запуск на водительском экране |

Показываются именно задачи (`RunningTaskInfo`), а не фоновые процессы: приложение без активной задачи в
списке не появится. `forceStopPackage` — жёсткий стоп: приложение при следующем запуске стартует с нуля
и теряет несохранённое состояние.

Отбор задач — `TaskListPolicy` (чистая логика, JVM-тест `TaskListPolicyTest`): один пакет — одна
запись в порядке появления задач, но если у пакета есть задача вне дисплеев виджетов, выбирается она,
чтобы тап по карточке переключал на видимую копию. Признак «в виджете» получает пакет, у которого все
задачи на дисплеях виджетов; дисплеи берутся из реестра Native (`embeddedDisplays`), а не из
эвристики. Приложение внутри виджета может вообще не попасть в `getRunningTasks` — тогда Native
добавляет его в список сам, по реестру `embeddedPackages`, с тем же признаком, но только пока жив
процесс пакета: реестр помнит о запуске и после `forceStopPackage`.

Тап по карточке виджетного приложения не поднимает его задачу (`moveTaskToFront` оставил бы её на
VirtualDisplay), а запускает приложение на водительском экране через `AppDisplayLauncher` — тот снимает
задачу с дисплея виджета и уведомляет хост (`notifyEmbeddedTaskLeft`), чтобы плитка не осталась с
мёртвой поверхностью. Режим окна выбирается по общему списку `voyahtune_fullscreen_apps`.

## Фиксация приложений

Булавка в верхней части карточки (повторное нажатие снимает) защищает приложение от «Закрыть все»:
зафиксированные пропускаются и в диспетчере задач, и в кнопке «Закрыть приложения» в «Дополнительно»
(её диалог об этом предупреждает). Обычная кнопка «Закрыть» на карточке работает всегда — фиксация не
запрещает закрыть приложение вручную. Список зафиксированных хранит Native в `NativePrefs`
(ключ `pinnedApps`, CSV), поэтому он переживает перезагрузку головы и не требует отдельных настроек в
интерфейсе; признак фиксации приходит в ответе `LIST` параллельным массивом `pinned`, а переключается
сообщением `PIN` (`pkg` + `pinned`), после которого Native сразу отдаёт свежий список. Повторная
фиксация и снятие не дублируют записи; удалённые приложения из списка не вычищаются.

## Протокол

Messenger-контракт определён в общем `SharedAndroid/.../common/TaskManagerProtocol.java`, ids 105–109
(не пересекаются с `SetModesService` 1–38, `SuspensionWidgetProtocol` 90–93, `ScenarioProtocol` 94 и
`EnergyWidgetProtocol` 100–103). `CLOSE_ALL` совпадает с существующим `MSG_CLOSE_ALL = 27`.

| Id | Направление | Данные |
| --- | --- | --- |
| `REQUEST` = 105 | RestoreMode → Native | — |
| `LIST` = 106 | Native → RestoreMode | `packages`, `labels` (параллельные ArrayList), `pinned`, `widgets` (параллельные boolean[]) |
| `CLOSE` = 107 | RestoreMode → Native | `pkg`; ответ — `LIST` |
| `SWITCH` = 108 | RestoreMode → Native | `pkg` |
| `PIN` = 109 | RestoreMode → Native | `pkg`, `pinned`; ответ — `LIST` |

`LIST` несёт четыре параллельных массива: `packages`, `labels`, `pinned` и `widgets`.

`TaskManagerActivity` биндится к `ru.big.town.anative.SetModesService` сама (`BIND_SET_MODES_SERVICE`), а
не через главный экран: активность открывается долгим нажатием дока, когда VoyahTune ещё не запущен.
Активность объявлена `exported` без дополнительного permission — как `MainActivity`, иначе хук родного
лаунчера (чужой процесс без нашей signature-пермиссии) не смог бы её стартовать.

## Проверки

JVM-тест `TaskManagerCardsTest` проверяет число слотов, необходимость карточки «Закрыть все» и ширину
карточки; `TaskListPolicyTest` — отбор задач (одна запись на пакет, приоритет копии вне виджета, признак
«в виджете»). Контракт фиксации и виджетного признака — `Packaging/tests/test_task_manager_pins.sh`.
Контракт хука дока — `Packaging/tests/test_launcher_dock_buttons.sh` (`node --check`,
компонент активности диспетчера, отсутствие прежнего перехода на главный экран, запись в
`ourInsetActivity`).

## Ограничения

Отбор задач и работа `moveTaskToFront` на автомобиле этим изменением не подтверждены: `getRunningTasks`
с `REAL_GET_TASKS` используется и в других местах Native, но прошлый widget запущенных приложений был
удалён как неработающий. Если список окажется пустым, потребуется другой источник (UsageStatsManager
или `IActivityTaskManager`). Геометрия шести карточек проверена только расчётом: 1920 px минус полоса
дока и промежутки дают около 285 px на карточку.

Приложения внутри виджетов попадают в список по реестру Native (`embeddedPackages`), который живёт,
пока жив процесс сервиса: он создаёт VirtualDisplay и теряет его вместе с процессом. «Закрыть» на
карточке такого приложения сначала снимает виджеты, в которых оно показывалось (`releaseEmbeddedDisplay`
и уведомление хоста), и только потом делает `forceStopPackage`: без этого следующая отрисовка главного
экрана запустила бы закрытое приложение заново. Плитка при этом убирается с главного экрана — так же,
как по её собственному крестику; настройку плитки пользователь после этого выбирает заново.
