# Яркость дисплеев

В настройках автомобиля управление яркостью использует таблицу уровней датчика
освещённости 0–7. Для каждого уровня задаётся один процент 1–100. Если записи нет,
сохраняется последняя яркость. Прежние условия преобразуются по первому совпадению.
Ночной режим задаётся отдельным включительным порогом датчика; по умолчанию — 1.
При переносе прежних ночных правил берётся наибольший охваченный ими уровень.
Порог работает независимо от наличия записи яркости для текущего уровня.

«Адаптивная яркость» включена по умолчанию. При включённом управлении по правилам
ручная регулировка через HiBoard обновляет процент текущего уровня или добавляет
отсутствующую запись. Native проверяет фактическую яркость выбранного дисплея;
неподтверждённые команды и неизвестный уровень датчика не сохраняются.
Одна таблица применяется ко всем трём дисплеям.

В «Главный экран» можно включить виджет «Яркость дисплеев» 3×1: День, Ночь, Авто.
День и Ночь переключают все дисплеи и приостанавливают подписку правил яркости
на датчик вместе с адаптивным обучением. Авто возобновляет включённые правила;
при выключенных правилах возвращает штатный автоматический режим.
Фары и сценарии сохраняют доступ к общему датчику.

Ручные изменения распознаёт модуль `brightness` единого runtime в процессе HiBoard.
Команды Native не проходят через этот перехват и не записываются как калибровка.
Для фоновых OEM-команд используется `FLAG_NOT_NOTIFY = 1`, чтобы SystemUI
не открывал центральный слайдер; подтверждение выполняется чтением OEM API.

Исследован локальный HiBoard 1.0.0 (versionCode 1, Android 11, системный UID)
и соответствующая декомпиляция SystemUI. Совместимость точек перехвата и подавления
индикации с другими OEM-прошивками требует проверки. Испытания на автомобиле
для этой реализации пока не выполнены.

Для доставки нужны обновлённые Native, RestoreMode и единый runtime/загрузчик.
Пересборка установщика не требуется: установочный контракт и GUI не меняются.
