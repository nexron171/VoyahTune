# Навигационный звук выбранных приложений

В разделе «Приложения и разделение экрана» → «Звук через навигационный канал»
выбираются приложения, которым нужен OEM-канал навигации. По умолчанию список пуст.
После изменения списка выбранные приложения нужно перезапустить: существующие
аудиопотоки сохраняют назначенный при создании маршрут.

## Реализация

- RestoreMode хранит список пакетов и передаёт его защищённому receiver Native;
  зеркало — `Settings.Global/voyahtune_navigation_audio_apps`.
- Загрузчик подключает отдельный модуль `navigation-audio.<package>` к основному
  процессу и процессам `<package>:<service>`. Существующие модули приложения
  сохраняются при включении и отключении звукового маршрута.
- AudioTrack и SoundPool получают атрибуты OEM stream **1**, MediaPlayer — перед
  prepare/prepareAsync и при явном назначении канала. MediaSession описывает этот
  же локальный канал. Политика приложения, ограничивающая захват звука, сохраняется.
- Параметры Android TTS копируются с назначением stream 1 и меткой пакета-источника:
  Native распознаёт такую озвучку, даже когда её воспроизводит отдельный TTS engine.
- Native отслеживает активные проигрыватели и фактическую активность канала 1.
  На это время он запрашивает OEM navigation focus: usage **12**, content **1**,
  gain **3**. Фокус освобождается через **250 мс** без активности; уровень музыки
  вручную не перезаписывается. Запросы media focus выбранного приложения
  замещаются этим владельцем, чтобы оно не переключало музыку на себя.
- Native получает `MODIFY_AUDIO_ROUTING` через manifest и системный whitelist:
  без него Android скрывает UID и теги чужих проигрывателей. `usesNonSdkApi`
  разрешает системному Native нужные OEM/hidden API. Отказы OEM-запроса и потеря
  владельца повторяются через **500 мс**; временная пауза сохраняет OEM-владельца.
- Общий с CarPlay [контроллер приглушения](../Native/app/src/main/java/ru/big/town/anative/NavigationMediaDucking.java)
  применяет один независимый VolumeShaper к активной Android-музыке и RDS:
  **20%** за **150 мс**, восстановление после последнего навигационного владельца.
  Только OEM focus оказался недостаточным для Яндекс Музыки при проверке на ГУ:
  запрос в Qinggan не заменяет Android focus, запускающий штатное приглушение
  Android-плееров. Собственный коэффициент не меняет громкость OEM, gain приложения,
  его маршрут или состояние play/pause.
- Выбор музыки требует stream **3**, usage **MEDIA/GAME/UNKNOWN** и достоверное
  имя пакета обычного application UID. Speech-контент, навигация, звонки, Siri,
  уведомления и системные проигрыватели с общим UID исключены. Для RDS разрешены
  только точные пакеты `com.adayo.service.dab` и `com.pateo.rdsapp`, поскольку
  AdayoDAB имеет системный shared UID.
- При навигации самого CarPlay его музыка RestoreMode не получает дополнительный
  коэффициент: sink уже обрабатывает iPhone `duckAudio`. Внешний навигатор из списка
  приглушает и музыку CarPlay. При пересечении подсказок владельцы независимы:
  окончание внешней навигации снимает её gain с CarPlay, а остальная Android-музыка
  остаётся приглушённой до окончания обеих подсказок. Радио получает тот же единственный
  private shaper и повторно не приглушается вторым нашим коэффициентом.
- Новые треки учитываются во время подсказки. При изменении роли уже работающего
  проигрывателя на навигационную прежний media gain снимается. После перезапуска
  Native оставшийся собственный shaper снимается со всех существующих проигрывателей,
  включая приостановленные, до принятия новых навигационных владельцев.

## Границы

В прошивке **AR.01.20260318170344.rc1** RdsApp запрашивает media stream **3**,
а **AdayoDAB 02.24.20240726.1 (30)** воспроизводит PCM через обычный AudioTrack
stream **3** и игнорирует `LOSS_TRANSIENT_CAN_DUCK`. Это не отдельный навигационный
канал. Контроллер проверяет точное имя пакета проигрывателя: AdayoDAB использует
общий системный UID, поэтому одного UID недостаточно для безопасного выбора радио.

Старое предположение о достаточности одного OEM focus для всех музыкальных приложений
опровергнуто проверкой пользователя: RDS приглушалось, Яндекс Музыка — нет. Новый
VolumeShaper для обычных музыкальных плееров локально проверен на уровне политики;
его слышимость и восстановление на конкретной ГУ ещё нужно подтвердить. Локальные JVM-тесты
и компиляции не подтверждают работу автомобиля.

Прямые OpenSL ES/AAudio-проигрыватели, обходящие перечисленные Java API, и звук
системных уведомлений через ранее созданные notification channels этим модулем
не переназначаются. Для конкретного приложения нужно проверить фактический путь.

Изменения поставляются вместе: Native APK, RestoreMode APK и обновлённый runtime.
Контракт Installer не меняется; его пересборка не требуется.
