# VoyahTune 3.22.0

## Статус

Код GitLab `master` и `master-od` объединён в `master-merged` и подготовлен для
итоговой ветки `master`. По решению пользователя этап объединения завершается
с фиксацией уже выполненных проверок, без дополнительной приёмки и пересборок.
Предварительные `3.22.0-od` и `3.22.0-pi` ещё не опубликованы; основной и
beta-каталоги не обновлялись. Финальные архивы после последних исправлений
и личная проверка автомобильных функций остаются отдельным этапом выпуска.

## Изменения

- Объединены Native и RestoreMode из GitLab `master` и `master-od` в общую базу
  исходников. Сохранены запуск голосового помощника после загрузки, настройки,
  виджеты, управление приложениями и механизмы восстановления обеих веток.
- PI сохраняет раннюю проверку режима движения в ограниченном 30-секундном окне
  и восстановление при открытии водительской двери и первом последующем переходе
  в Drive. OD сохраняет восстановление через ACC hooks. Общий код выбирает
  совместимый механизм по инфраструктуре установленного релиза; события одного
  механизма не запускают второй.
- Apollo в обоих вариантах использует поведение `master-od` по согласованному
  решению. Остальные PI/OD hooks и их настройки разделены по исходным веткам.
- В PI включён отдельный RunYN: выбор приложения для навигационной области
  приборной панели. Его APK собирается с версией PI-релиза, а хеш включён
  в подписанные metadata Native и RestoreMode. При установке сохраняются данные
  RunYN; его функция на приборной панели требует проверки на автомобиле.
- Исправлено применение DPI после перемещения или обмена приложений между
  областями экрана: меняется профиль фактически размещённого приложения.
  Настройка другого выбранного приложения не перезаписывается.
- Исправлена гонка голосового кэша: завершившаяся фоновая сборка не возвращает
  устаревшее содержимое после инвалидации; срок действия использует монотонное время.
- Native Android-виджет запуска приложений переведён на поддерживаемую коллекцию
  RemoteViews с отдельными идентификаторами экземпляров и действиями элементов.
  Фоны трёх кнопок используют явный ripple: отрисовка не зависит от AppCompat-темы
  стороннего launcher. Это отдельный виджет Android, а не плитка внутри RestoreMode.

## Инфраструктура и состав релиза

Скрипты и hooks находятся раздельно в `Packaging/pi/` и `Packaging/od/`.
PI использует Go `loaderFrida` и `injects.json`, OD — shell loader и свой набор
hooks. Сборщик упаковывает только выбранную инфраструктуру; основные Android APK
собираются из общих исходников. PI дополнительно включает RunYN.

При сборке содержимого релиза обязателен ровно один флаг:

```sh
./make_release.sh 3.22.0 --od --payload
./make_release.sh 3.22.0 --pi --payload
```

Результат — `payload_3.22.0-od.zip` и `payload_3.22.0-pi.zip`. Инфраструктура
проверяется по manifest и metadata внутри подписанных APK; версия и суффикс
должны согласовываться. Флаг сборки не является пользовательской настройкой
в приложении. Для смены PI/OD сначала удалите VoyahTune, затем самостоятельно
выберите и установите релиз с другой инфраструктурой. Это порядок действий
пользователя; GUI не определяет и не выполняет специальный переход.
[Состав payload](installer-payload.md), [порядок сборки](releasing.md).

GUI Installer **1.5.0 общий** для PI и OD. Один каталог может содержать обе версии,
и GUI позволяет выбрать любую из них. OTA-служба выбирает только релизы своего
суффикса до определения последней версии и скачивания; старые версии без суффикса
считаются OD. Суффиксы `-pi` и `-od` обозначают инфраструктуру и сами по себе
не означают beta-канал.

Для этого релиза нужна пересборка установщика: изменились проверка инфраструктуры,
процесс установки и удаления, встроенный remover и проверка PI loader. Payload
требует Installer не ниже **1.5.0** и capability `infrastructure-v1`. Последующие
совместимые изменения только APK/hooks не требуют новой версии GUI.
[Архитектура установщика](installer-architecture.md).

## Выполненные локальные проверки

- JVM-тесты, debug-сборки и Android lint Native/RestoreMode прошли. После
  исправления фонов RemoteViews набор Native выполнен повторно и также прошёл.
- RunYN прошёл JVM-тесты и release-сборку с версией `3.22.0-pi`.
- Проверки Packaging для обоих вариантов, тесты OD loader и PI Go loader
  с детектором гонок прошли.
- Пройдены Rust-тесты общего Installer и Updater для PI/OD, а также тесты
  публикационных скриптов с локальными подменами S3. Загрузка в S3 не выполнялась.
- Первые payload обоих вариантов и общий macOS Universal Installer 1.5.0
  собраны локально. Проверены хеши артефактов, подписи APK, подписанные metadata
  и соответствие инфраструктуры составу payload.
- На Android 11/API30 эмуляторе выполнены предварительные проверки OD и PI
  через общий GUI. Подтверждены запуск Native, RestoreMode,
  Updater и PI RunYN, работа процессов загрузчиков. Итоговая приёмка каждого
  варианта после удаления не выполнялась. Проверка Android-виджета
  обнаружила ошибку зависимости от темы launcher; исправление подготовлено,
  повторная runtime-проверка после новой установки не выполнялась.

Эти результаты относятся к выполненным этапам, а не заменяют проверку итоговых
архивов после последних исправлений. Окончательные хеши, повторная установка,
проверка действий виджета и личная приёмка ещё не зафиксированы как завершённые.

## Совместимость и ограничения

Основная целевая платформа — официальные SE и Sport+ 2025–2026, Android 11.
Сохранение инфраструктуры PI и OD не доказывает поддержку любой другой комплектации
или прошивки. Эмулятор использует тестовые OEM-службы и не подтверждает работу
CAN, ACC-восстановления, Apollo, приборной панели или эффектов Frida на автомобиле.

Запущенный loader и его heartbeat подтверждают работу процесса, а не выполнение
OEM-команды. Отправка команды также не является физическим подтверждением.
Работоспособность автомобильных функций и итогового релиза подтверждает пользователь.
