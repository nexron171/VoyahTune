# VoyahTune 3.16.0

## Изменения

- Выбранные пользователем режимы вождения и энергии отделены от наблюдаемого
  состояния автомобиля: штатный сброс больше не подменяет сохранённый выбор.
- Восстановление режимов использует стартовую команду и перехваты известных
  OEM-сбросов; повторное применение режимов из проходов Native по двери/D удалено.
- При выходе из Forced EV восстанавливается настроенный режим энергии.
- Улучшено восстановление агентов после ошибок и перезапуска OEM-процессов.
  Удалён опасный для исследованной H97X ART обход Java heap.
- Выбор режима через салонную кнопку VehicleAir сохраняется как пользовательский
  и отменяет ожидающее восстановление прежнего режима. Автоматический выход из
  Outing не подменяет сохранённый выбор; сохранена история возврата средней подвески.
  Новый перехват проверен локальными тестами, на автомобиле ещё не проверен.

Подробности и границы проверки на головном устройстве описаны в
[алгоритме восстановления](early-drive-mode-restore.md) и
[описании ACC-перехвата](acc-restore-hook.md). Эти проверки исходных исправлений
не заменяют отдельную проверку установки нового архива 3.16.0.

## Состав выпуска

Общий payload 3.16.0 предназначен для совместимого Installer 1.2.0 и OTA.
Установщики собраны отдельно для macOS Universal (Apple Silicon и Intel),
Windows x64 и Windows x86. Версия установщика остаётся 1.2.0; payload и
установщики имеют независимые версии. Windows x86 предназначен для 32-битной
Windows 10. Проверка сборки не подтверждает запуск на Windows или работу на машине.

Файлы выпуска размещаются в `voyahtune/v3.16.0/` в Yandex Object Storage.
Каталог OTA хранится в [Releases/ota/index.json](../Releases/ota/index.json).
Установщики скачивают payload из каталога или импортируют локальный ZIP.

## Повторная сборка с новым интерфейсом обновлений

По прямому запросу владельца выпуск заменяется под прежним номером 3.16.0.

- Новый нативный экран апдейтера соответствует согласованному прототипу.
- Фоновый опрос не отключает кнопки и не пересоздаёт экран.
- Установка показывает прогресс по завершённым шагам; проверка архива,
  подготовка, reboot и проверка запуска — бегающий индикатор.
- Настройки содержат выбор Яндекс DNS; root-служба применяет его после APK,
  перед перезагрузкой. Текущее неопределённое/внешнее состояние не заменяется.
- Журнал остаётся на ГУ для USB-диагностики, его кнопки убраны из интерфейса.

Для получения нового APK апдейтера и root-службы нужна установка через USB.
Обычное OTA не заменяет эти компоненты. Уже установленная прежняя 3.16.0
не принимает для повторной OTA-установки архив с другой контрольной суммой.
Проверены 21 Rust-тест и 5 JVM-тестов updater, локальные Android/ARM64 сборки.
Новый Android UI и изменение DNS на головном устройстве ещё не проверены.

## Расширенный автосвет

- В настройках рядом с выключателем автосвета добавлена «Расширенная логика
  автосвета», по умолчанию выключенная.
- SWReason 0/1 выбирают выкл, 3/5/6/7 — ближний. Для 2/4 выбирается штатный
  Auto при включённом автодальнем VehicleSettings, иначе ближний.
- Перед автоматической командой расширенной логики синхронно читается текущее
  значение штатного автодальнего; при недоступном значении выбирается ближний
  для 2/4. Подписка дополнительно реагирует на изменение переключателя.
- Автоматически выбранный Auto не вызывает принудительный возврат ближнего.
- Исправлена повторная команда OEM Auto: перед отправкой читается LightStatus,
  уже активный Auto не переключается повторно. На машине подтверждено, что
  повтор `AUTO_LAMP_SWITCH` возвращал ближний при неизменном SWReason.

- Рядом с переключателем отображается `SWReason: число — описание`.
- При подключении CAN и открытии настроек Native читает текущий SWReason через
  OEM TX57, не дожидаясь изменения сигнала. Исправлена подписка на события подключения.

[Подробное описание автосвета](auto-light.md). На подключённом автомобиле проверены
активные SHA-256 новых Native/RestoreMode, запуск службы и отображение
`SWReason: 4 — Запуск в темноте`. Это не подтверждение физического выполнения всех
режимов фар. После последних доработок прошли 327 JVM-тестов Native и 94 RestoreMode.

## Исправление активного APK после USB и OTA

По прямому запросу владельца payload и все три опубликованных установщика заменяются
под прежними номерами: VoyahTune 3.16.0 и Installer 1.2.0. Старые архивы не сохраняются.

- USB-установщик проверяет SHA-256 APK, фактически выбранного PackageManager,
  вместо проверки только номера версии и наличия процесса. Старая копия Native
  в `/data/app` больше не может незаметно перекрыть новый системный APK.
- При несовпадении Native или интерфейс Updater обновляется через `pm install -r`
  с сохранением данных; активный APK повторно проверяется. Проверяется и RestoreMode.
- Root-служба Updater сверяет активные Native/RestoreMode с payload сразу после
  установки и после перезагрузки. Ложный `Success` или несовпадающие байты приводят
  к ошибке, а не к подтверждению обновления.

Изменение исполняемой логики требует новых установщиков macOS Universal и Windows
x64/x86. Контракт payload совместим, поэтому версия Installer остаётся 1.2.0.
Новая root-служба Updater доставляется через USB; обычное OTA её не заменяет.
Для повторной установки изменённой 3.16.0 также используйте USB.

Проверены 40 Rust-тестов Installer, 22 root-службы Updater, Svelte check и три
сценария тестового ADB: замена старого активного APK с сохранением данных, отказ при
ложном Success и обычная установка/ремонт/удаление. Проверка сборки установщиков
не заменяет запуск Windows GUI или полную USB/OTA-приёмку на автомобиле.
