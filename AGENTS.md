# Работа с VoyahTune

VoyahTune — Android-приложения и системная интеграция для Voyah Free.
Основная целевая платформа: официальные SE и Sport+ 2025–2026, Android 11.
Поддержку других комплектаций и прошивок подтверждай отдельно.

## Структура проекта

- `RestoreMode/` — интерфейс, настройки, главный экран и голосовой помощник.
- `Native/` — привилегированный сервис, OEM API, CAN и управление приложениями.
- `Packaging/` — системные перехваты, загрузчик, установочные скрипты и их проверки.
- `Installer/` — GUI на Tauri/Svelte, общий Rust-движок и CLI.
- `Utils/` — вспомогательные инструменты и тестовое окружение.
- `Releases/` — локальные результаты сборки; исходники комплекта находятся в `Packaging/`.

## Документация и рабочие материалы

- Инструкции, справочники, актуальное описание реализации и историю выпусков храни в `Docs/`.
- Планы, аудиты, разборы и чеклисты храни в корневой `Plans/`.
- `Plans/` игнорируется Git: не добавляй её принудительно и не ставь на её файлы ссылки из публикуемой документации.
- `tmp/` содержит локальные APK, декомпиляции и материалы исследований; их может не быть в другом checkout.
- Существенные подтверждённые сведения для сопровождения переноси из рабочих материалов в документацию.
- В этом файле держи устойчивые правила проекта; результаты отдельных задач оставляй в `Plans/`.

## Реализация и совместимость

- Учитывай оба варианта Android-приложений: `full` и `light`. Возможности Full не должны становиться обязательными зависимостями Light.
- Используй существующие OEM-транспорты и обработчики событий; не дублируй доступ к CAN без необходимости.
- При изменении протокола между RestoreMode и Native проверяй обе стороны.
- Различай наличие поля в OEM API, успешную отправку команды и подтверждённое выполнение автомобилем.
- В выводах по декомпиляции указывай исследованную версию и ограничения; общий SDK не доказывает поддержку функции на конкретной машине.
- Не выдавай фиксированные значения интерфейса за измерения датчиков или тест на эмуляторе за проверку на автомобиле.

## Проверки

Выбирай проверки по затронутому компоненту; изменение документации не требует полной сборки.
Команды ниже выполняются из указанного каталога:

- `Native/` или `RestoreMode/`: `./gradlew testFullDebugUnitTest testLightDebugUnitTest` — JVM-тесты.
- В том же Android-проекте: `./gradlew assembleFullDebug assembleLightDebug` — проверка сборки обоих вариантов, когда изменение её затрагивает.
- `Installer/`: `cargo test` — тесты основных Rust-компонентов workspace.
- `Installer/desktop/`: `npm run check`; для проверки сборки интерфейса — `npm run build`.
- Из корня: относящиеся к изменению скрипты `Packaging/tests/`; инструкции окружения — в `Docs/releasing.md`.
- Перед завершением проверяй `git diff --check`, состав изменений и локальные ссылки в изменённой документации.
- В результате называй выполненные проверки и ограничения. Установку на машину, испытания и публикацию выполняй в рамках явно согласованной задачи.
