# Релизы VoyahTune

Все новые сборки единые. Один USB/OTA payload содержит Native, RestoreMode,
RunYN, root-службу обновлений и runtime из `Packaging/new/`.
Manifest использует `infrastructure: unified`, версия не имеет инфраструктурного
суффикса. Особенности OEM выбираются адаптерами, установка RunYN — по модели.

[Выпуск](../Docs/releasing.md) · [Состав payload](../Docs/installer-payload.md) ·
[Протокол](../Docs/installer-protocol.md) ·
[Сборка GUI](../Installer/BUILDING.md).

## Сборка

Номер ниже условный. Для stable используйте `versions.json.voyahtune`, для beta —
согласованный номер с `-beta`. Минимум OTA определяется совместимостью root-службы.

```sh
./make_release.sh 4.5.0 --payload --minimum-ota-version 4.5.0
```

Результат:

```text
Releases/build/installer-payload-4.5.0/
Releases/dist/payload_4.5.0.zip
Releases/dist/payload_4.5.0.json
```

Команда собирает runtime и приложения, создаёт и проверяет recipe/manifest.
Для последующего релиза без замены службы сохраняйте прежний минимум OTA.
Самостоятельная сборка GUI не собирает Android:

```sh
./Installer/scripts/build-all-macos.sh --mac
```

Версии GUI и VoyahTune независимы. Изменение агентов в пределах поддерживаемого
recipe обычно требует только нового payload. Новый обработчик установки, capability
или встроенный ресурс GUI требует соответствующего обновления установщика.
Фиксированный формат payload без внешних манифестов требует Installer 1.8.5.

## Исходники

| Каталог | Назначение |
| --- | --- |
| `new/` | Единые агенты, Go-загрузчик, конфигурация, build/check и boot-ресурсы |
| `installer/` | Вспомогательные установочные ресурсы; роли заданы в `release-core` |
| `system/` | Общие системные роли, включая whitelist и root-службу OTA |
| `tests/` | Поведенческие проверки настроек и установочных helpers |
| `vendor-overlay/` | DNS overlay и его происхождение |
| `branding/` | Иконки и другие ресурсы оформления |

Native/Java runtime находится в `new/`, общие установочные helpers — в
`installer/common/`. Очистка прежних установок
сохранена в recipe, списках устаревших путей и общем движке. Не редактируйте готовые файлы в `Releases/` вместо исходников.

## Runtime и обновление поверх

[Устройство единого runtime](new/README.md) описывает встроенный реестр агентов, выбор OEM
по доступным классам/методам, ready/health, ограниченные повторы, crash-loop и
диагностику. Результат `new/build.sh` самодостаточен, размещается в
`/data/local/bin/voyahtune-new/` и запускается через существующий `voyahtune_load`.

Общий сборщик использует типизированные роли `release-core`; их хеши и digest
плана установки входят в подписанные metadata APK. Payload содержит `common/` без внешнего манифеста. Все компоненты выпускаются согласованно. RunYN присутствует
в архиве с `condition: except-h97xy`: на H97X/H97Y установка пропускается.

USB и OTA блокируют новые инъекции, принудительно завершают собственные процессы
без ACK агентов, заменяют файлы и очищают точные устаревшие пути из
`new/config/retired-files.txt`. Затем обязательны перезагрузка и проверка
`voyahtune-loader --check-hooks`. Ошибка после начала остановки также приводит
к попытке reboot с сохранением блокировки и первичной ошибки.

Первое обновление несовместимой root-службы требует USB. Совместимая служба
выполняет дальнейшие OTA тем же архивом, сохраняя собственный бинарник и boot-контракт.
Полный автоматический откат всех APK и системных файлов не предусмотрен.
[Ограничения OTA](../Docs/ota-updater.md).

## Проверки и эксплуатация

Минимальные проверки выбирайте по изменённым компонентам. Для нового runtime:

```sh
sh Packaging/new/check.sh
sh Packaging/new/build.sh
```

Локальные проверки моделей OEM/ART не подтверждают работу всех прошивок.
На машине отдельно проверяются холодный старт, сон/пробуждение, ACC, Power Hold,
оба экрана и доступные функции приборной панели. `build.sh` сам по себе ничего
не устанавливает и не публикует.

Подробные функциональные контракты и результаты прежних исследований:
[восстановление настроек](../Docs/acc-settings-persistence.md),
[док и перенос окон](../Docs/system-server-geometry.md),
[CarPlay](../Docs/carplay-diplay.md), [клавиатура и виджеты](../Docs/system-widgets.md),
[Power Hold и голосовые действия](../Docs/voice-control.md).
Исторические имена ресурсов в этих разборах не являются командами выпуска.
