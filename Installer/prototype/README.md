# Интерактивный прототип установщика

Откройте `index.html` в браузере. Сборка, установка зависимостей и интернет не нужны.
Все подключения и операции демонстрационные: прототип не запускает ADB, не читает
устройства, не отправляет сетевые запросы и не изменяет автомобиль.

Для локального HTTP-preview из этого каталога:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

## Что можно согласовать

- Три плитки Full / Light / удаления и пояснения к наборам.
- Ручное обновление подключения, ошибки 0/нескольких устройств, unauthorized/offline,
  ручное подтверждение единственного автомобиля и проверку перед запуском.
- Реальный алгоритм кода инженерного меню, дату по Пекину, ручной выбор даты и подсказку попробовать код на 1 больше или следующий день.
- План установки и перехода между наборами, DNS, подтверждение удаления данных.
- Этапы выполнения, прогресс передачи, ошибку с причиной и исходным выводом,
  повтор, остановку/продолжение, журнал и скачивание демонстрационного JSON-отчёта.
- Успешное завершение установки и полную очистку обоих наборов при удалении.

В панели демонстрации под окном выберите подключение и нажмите «Обновить» внутри
мастера. «Сейчас в автомобиле» меняет найденный набор. Сбой воспроизводится один раз,
поэтому после ошибки можно пройти успешный повтор. Ошибка бэкапа относится к установке,
ошибка завершающей очистки — к удалению. Обрыв соединения в сценарии бэкапа — событие
симулятора: для повтора связь считается восстановленной, если выбран «Один автомобиль · готов».

## Перенос в реализацию

`styles.css` содержит дизайн-токены и оформление компонентов. `model.js` содержит
описания наборов, каталог состояний, шагов и алгоритм инженерного кода. `app.js` —
представление экранов и переходы. `demo-adapter.js` — сменный mock-адаптер с событиями
`step-started`, `progress`, `step-succeeded`, `failed`, `completed`.

При реализации на Svelte переносим разметку по экранным компонентам и сохраняем
тексты/токены. Mock-адаптер заменяем мостом к Tauri sidecar; имитация выполнения не
является production-движком. Проверки доступа, единственности устройства, схемы событий,
повторы, таймауты и безопасная отмена должны исполняться в Rust core/CLI. `model.js`
содержит демонстрационные данные об автомобиле, а не базу совместимости.

Базовый расчёт кода совпадает с `AdvanceActivity.engineeringPassword()` в RestoreMode. В
прототипе источник времени — компьютер или явно выбранная пекинская дата; часы
реального ГУ не читаются. Точный алгоритм смены кода на автомобиле неизвестен; интерфейс не обещает, что он меняется точно в пекинскую полночь. Целевой движок реализует эту функцию в Rust с теми же
контрольными примерами.

Связанный документ: [архитектура](../../Docs/installer-architecture.md).

Проверки модели: `node --test model.test.cjs`.
