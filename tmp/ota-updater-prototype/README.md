# HTML-прототип обновлений VoyahTune

Откройте `index.html` прямо в браузере. Сборка, зависимости и сеть не нужны.
При необходимости HTTP-просмотра из корня проекта:

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory tmp/ota-updater-prototype
```

Макет использует дизайн-систему настроек RestoreMode: Arimo, голубой акцент,
карточки с радиусом 22 px, боковую навигацию 300 px и закреплённые действия.
Шрифт распространяется по [SIL OFL 1.1](Arimo-OFL.txt).
Холст 1920 × 720 масштабируется под окно; содержимое прокручивается под шапкой
с ускоряющейся маской 100→0% без блюра. Слева зарезервировано 145 px под док,
сверху 32 px под условную системную панель. В Android используются реальные insets.

## Просмотр

- Список «Состояние» переключает все основные экраны без ожидания.
- «Скачать» демонстрирует загрузку и проверку, затем ждёт подтверждения установки.
- «Установить» открывает подтверждение. Далее показаны подготовка, установка,
  перезагрузка, проверка запуска и успех. Реальной перезагрузки нет.
- «Автопрогресс» включает/приостанавливает развитие демонстрационного сценария.
- При ошибке причина показана прямо на экране; предложена установка через USB.
- Настройки содержат адрес каталога и повторную установку текущей версии.
  Адрес хранится только в памяти страницы и не используется для сетевых запросов.
- «Уведомление о релизе» показывает скрываемый диалог; скрытие ничего не скачивает.
- «В VoyahTune» показывает подсказку вместо открытия реального приложения.

Версии, размер, часы, ошибки и состояния службы — демонстрационные значения.
Описание изменений релиза не выдумывается: каталог его сейчас не содержит.

## Обновление экрана

Периодический опрос имитируется каждые 2 секунды. Элементы DOM постоянны,
текст и прогресс изменяются только при отличии значения. Доступность действий
зависит от этапа операции, а не от каждого запроса состояния. Нет общей
анимации появления, сброса фокуса или пересоздания экрана при опросе.

Этот стиль перенесён в Android Updater 0.5.0. Прототип остаётся автономной
демонстрацией: он не обращается к root-службе и не скачивает релизы. При проверке
эмулятора состояния подставлялись отдельной временной instrumentation-оснасткой,
которая затем удалена. Логика root-службы и доставка OTA этой задачей не менялись.
Для интерфейса проверены assembleDebug и семь существующих JVM-тестов.

## Прогресс установки и DNS

Полоса установки заполняется по числу завершённых шагов из восьми, а не по времени
или числу записанных байтов. На текущем шаге процент стоит до его завершения.
В демонстрации завершение имитируется таймером; сверху можно выбрать конкретный шаг.
100% означает готовность к перезагрузке, успех показывается только после проверки запуска.

В настройках рядом с URL добавлен переключатель Яндекс DNS. Начальное значение
определяет демонстрационный селектор «DNS на ГУ»: Яндекс → включён, стандартный →
выключен; неизвестный → изменение недоступно. Сохранение выбирает действие для
следующей установки, но сразу не меняет DNS. На шаге DNS включение устанавливает
Яндекс DNS, выключение возвращает стандартный; совпадение сохраняет текущий DNS.

Нативный интерфейс показывает прогресс из завершённых шагов службы; в прототипе
таймер служит только для иллюстрации. Возможности DNS определяются ответом службы.
